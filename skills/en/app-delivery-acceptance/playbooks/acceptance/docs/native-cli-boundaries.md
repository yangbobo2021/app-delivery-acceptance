# Official CLI, role and service boundary

Use `node_modules/.bin/playbook run --with OVERLAY --no-provision --json` directly. The standard binary loads every public registry. Configuration generation discovers actual manifests, including internal finder/implementer/evaluator, preparation, repair and review roles. `--roles` applies to all of them; no `ACCEPTANCE_ROLE_CONFIG` or private launcher is required.

The CLI package pins **local source builds**, not published releases: Playbook `18.1.1-acceptance.20261028.2` and Cligent `0.36.2-acceptance.20261028.2`. Their tarballs and source patches are in `vendor/`. Do not infer that npm public versions contain those changes. The extra metadata and native event options are optional host capabilities for the CLI, not prerequisites for a SPEX artifact. Both execute roles and children through the official ports and retain the same business gates.

The host's configured role supplies Agent, model, effort, player identity and permission ceiling. The package only reads local Agent configuration to bind service identity to attempt evidence. Actual authentication/provider configuration belongs to the native Agent. Credentials must stay out of overlays, requests and reports. OpenCode requires explicit `provider/model` and an actual CLI on PATH. Claude can use the same compatible model service as OpenCode through its native ANTHROPIC environment settings.

Independent roles have distinct player IDs. The CLI's enhanced profile retains its explicit fresh-attempt and native-event behavior. Standard SPEX ports use host-led continuation and full current-task Prompts, without claiming provider-fresh sessions. Directory, permissions and image-reading requirements remain workflow Prompt contracts with actual file/evidence checks. Standard result projections are labelled as such, not invented native events. See [Agent/runtime evidence](agent-runtime.md).

Build a native SPEX release with `node bin/build-spex.mjs --output NEW_FOLDER --org YOUR_ORG`. Install that folder through SPEX Playbooks, enable the parent and needed children, and bind their Players in the UI. No `npm ci`, CLI overlay or absolute source checkout is needed by the installed artifact. See [SPEX installation](spex-installation.md).

A working-directory setting or permission request is not proof that tools ran. Check recorded init/model identity, tool events, process command receipts, file hashes and independently validated business results. Missing service configuration or unsupported visual capability blocks the corresponding claim. The current migration validation report states the actual tested agents and limitations.

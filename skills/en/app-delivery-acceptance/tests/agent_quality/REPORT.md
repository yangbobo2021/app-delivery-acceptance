# 测试 SKILL Agent 质量与可移植性验证报告

日期：2026-10-23。基线：`6b51b96e128eb93c907326603934bf7334a666b0`；改进分支：`codex/agent-portability-quality`。

本轮测试与复盘已经完成。结论有条件：主流程在代表性 macOS、Linux 项目上能够完成真实工作，能区分产品失败、测试错误和证据不足；发现的通用路径、场景设计、关键阈值和失败证据保留问题已修改并复测。覆盖率自动准备仍有明显成本和工具链限制，不能宣称所有项目首次运行均无需干预，也不能宣称任意电脑、语言和系统已经得到验证。

## 方法与判据

按用户目标评价每个职责：能否围绕冻结场景找到真实支持、识别必要缺口、避免冗余，给出可理解且可核对的结论。格式正确、命令成功、引用校验与语义质量分开记录。反向样例包括产品缺陷、额外格式约束、浅层成功、入口故障、截图遮挡、缺图、边界漏测和同次修改合同，不能把“流程能运行”当作质量通过。

使用真实原生 Agent 调用，模型为调用方当前 `Codex / gpt-6.1-sol / high`，SDK `0.162.1`。没有替换账户、模型或服务。预期答案及变异代码留在模型项目之外。独立只读复核先看原始要求与源码，不看问题清单或父代理结论；对场景、人工内容保留、UI像素和局部修复完成了三轮审查。完整场景与停止规则见 [PLAN.md](PLAN.md)。

## 真实串联与覆盖率限制

Python/Linux完整链路完成：新环境 → 覆盖率准备 → 复用用例 → 评估 → 宿主真实执行 → 冻结 → 独立复审 → 补等量边界 → 新执行与采集 → 新复审通过。coverage.py7.10.7负责原生数据、合并及统计；保留CLI文件的零命中分母，没有拿探针充当业务命中，也没有把单文件100%说成全项目验收。

覆盖率准备首次Python与Node都失败，宿主均拦截。Python第二轮四个零/非零探针通过，但完整prepared校验发现内部工具元数据不一致；第三轮按原失败证据最小修正后准备通过。总计约573+476+162秒，说明这仍是耗时且可能需多轮的环节，不宜向用户承诺快速首跑成功。

Node25/macOS第二轮为partial：直接进程探针通过，并实际产生一次有效HTTP用例采集；npm/node:test子进程路由仍受Inspector限制。独立复审发现已有测试还缺少两次回执各自存在的断言，原生修复补了断言，但统一调试入口失败，最终正确停为`repair_parked`。没有据首次执行或旧测试通过宣布修复后通过，也没有擅自关闭用户要求的覆盖率。这项重要可用性限制保留，经过两轮有依据的探索后不再深挖单一工具链。其他Node版本/路由能否避开该限制仍需实测。

较早的Mac评估/复审漏掉等量边界，是本轮发现的质量缺陷。旧回答和归档保留用于复盘，不能继续作为当前设计充分性的依据。改进后新评估与新独立复审都指出该缺口；已有等量样本的余额项目仍判充分；Linux完成了实际补测。反例比“模型说充分”的自评更能证明这项改进。

## 修改与回归

通用修改见 [FINDINGS.md](FINDINGS.md)：标准`fileURLToPath`转换五个入口；逐状态视觉要求；跨分支保护与合并风险自查；关键阈值检查；探针前冻结失败适配器和源码并在后续复核其未变；覆盖率按证据有限重试的调用规约。没有添加Python、Node、KeySync或某个操作系统的业务分支。语言专用适配器留在独立测试项目中。

Mac已有Python回归共537项通过，覆盖32个tests文件及20个v4文件；Agent配置适配10项通过。Linux同52文件运行中有一项出现xstate暂不可用，单项隔离复测通过，随后整文件23项隔离复测也全部通过，首次失败仍保留。并发模型测试还出现过一次配置读取失败，新目录原生重测成功，原因未完全证实，不能据此宣布并发依赖重建稳定。运行会重建依赖的Skill自身回归时应与真实模型工作流隔离。

Node legacy provider探针需要专用prepared参数和依赖，无参调用失败不计作v4产品缺陷；Python大范围unittest discovery有同名模块导入冲突，本轮按每文件独立进程执行。新测试代码编译、修改后的Node语法及Git空白检查通过。此处保留了测试工具自身的问题，没有抹掉失败记录或混入Agent通过率。

## 交付边界与证据

本轮目标是完成有反例、有复盘的验证与必要通用改进，并交付已知限制；不是证明无限项目集合。对原始业务合同尚未明确、真实设备不可访问、平台没有实测的情况，应保持待确认/未实测。依赖冷安装、模型耗时与覆盖率生成的波动仍存在；更广的语言、网络和硬件矩阵需要新的真实样本，不能由这份报告推断通过。

PLAN中的扩展条件也明确处置：真实消费端“资料格式有效但不可用”、生成场景自身附加政策的责任分流、第二语言逆向、依赖入口位于子目录的运行准备、真实断电或外部服务副作用后的恢复，没有追加专门的原生端到端样例。相关浅层断言、测试过约束和宿主恢复协议已有对照，但不等价于这些真实条件已经实测。历史回填/迁移、真实人工操作通过与source-free自动化黑盒也没有执行。它们列为后续覆盖缺口，本轮优先关闭已观察到的高影响通用问题，不为凑满矩阵反复增加相近正常样例。

原始输入、模型回答、实际命令、日志、版本、引用、截图、原生计数与首次失败分别保留。运行环境安装物、认证、缓存不作为结果发布。Mac资料位于本机本轮`agent-quality-20261023-*`输出；Linux资料按明确选择复制到同批次evidence目录：1124个文件、约5.7MB，含文件哈希清单，并重新核对24个冻结源码/适配器副本。Linux容器在证据保存后删除；测试fixture中的完整验收结束后才清理current指针。提交与推送状态以仓库Git记录为准。

复现入口和语义审阅要求见 [README.md](README.md)。后续维护应保留正常与反向对照，不用越来越多的固定关键词或项目特判替代Agent的职责判断。

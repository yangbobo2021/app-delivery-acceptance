# 本轮问题与处置

这里记录已观察到的问题，不将测试设计中的假设当作缺陷。原始证据留在本机验收输出，不将会话、机器路径或认证资料打包到 SKILL。

| ID | 级别 | 影响与依据 | 处置及复测 |
| --- | --- | --- | --- |
| AQ-001 | P1 | Linux 全新安装、同模型预检成功，但 SKILL 目录含中文/空格时，场景入口将文件 URL 的 `%20` 和百分号编码直接交给 Python，脚本实际存在仍报不存在。其他使用同一文件 URL 转换方式的用例、覆盖率、修复、复审入口也受影响。 | 使用 Node 标准 fileURLToPath 转换真实文件系统路径；保留原失败，在同一 Linux 特殊目录下复测真实工作流，并覆盖其他受影响入口。 |
| AQ-002 | P1 | 独立语义核对发现 Web 场景同时要求输入状态和成功状态中的输入框、提交控件、新事项全部可见。新增前结果尚不存在，成功后表单可以正常关闭；这个额外条件可能拒绝合法交互。 | 视觉要求按状态中用户任务需要的实际元素表达；保留原生成记录，使用原场景及不同交互的隐藏样例复测。 |
| AQ-003 | P1 | Linux Q04 的空标题拒绝与原始事项保护合并为 P1，理由只描述影响使用，低估了该场景实际能检出的原始数据删除/改写。Mac 对照正常，说明输出存在波动。 | 场景自查逐条判据检查后果；优先按风险拆分，仍合并时按有依据的最高影响评级。重跑原样例，不以结构通过代替语义核对。 |
| AQ-004 | P2 | Linux Q03 的配置只读保护未检查已经选定的环境变量覆盖分支，可能漏掉该分支回写配置的实现。 | 在已有代表操作上核对跨分支保护条件，不扩展全排列。与 AQ-003 共用通用自查改进及复测。 |
| AQ-005 | P1 | Node/macOS 和 Python/Linux 的首次覆盖率准备均未通过宿主零/非零探针。Node 工具读取未包含源码、npm 路由生命周期不完整；Python 零命中原生快照被适配器当作无效。宿主正确阻断，未交付可用状态。 | 保留原始输入、原生数据和失败适配器，再给原生 Agent 一轮基于证据的最小修正。按第二轮结果决定是否继续，不能人工代修后声称 Agent 已能工作。 |
| AQ-006 | P2 | 覆盖率适配器原来只在探针通过后归档；失败重试可能覆盖原始脚本，影响复现。 | 验证路径及产品不变后、探针执行前冻结源码和适配器，写入哈希清单；成功语义仍由探针和准备门禁决定。 |
| AQ-007 | P1 | 同样的两侧样本缺少合法等于边界：早期用例评估与 Mac 执行复审判充分/通过，Linux 复审指出把 `<` 改成 `<=` 的错误仍可通过。说明原规则下关键阈值检查存在波动。 | 在查找/复用、评估、独立复审中加入有原文依据的决策阈值反例检查。新评估与 Mac 再复审均指出必要缺口；有等量样本的独立余额项目仍判充分。Linux 原生修复只补等量样本，保留原用例，重新采集和复审通过。旧判定与原始证据保留，不能再作为当前充分性结论。 |

AQ-001 已在特殊路径下完成原生场景、用例实现、覆盖率、差量修复和执行复审入口验证。AQ-002 在 Web 与桌面向导场景复测中消除了跨状态不当要求；AQ-003/004 原样例重跑已补足评级和保护分支；AQ-006 的失败及成功尝试均有探针前源码快照。

AQ-005 按投入边界处置：Python/Linux 在第三次有明确依据的修正后准备完整通过，真实用例的采集、收尾、报告核验及复审已完成。Node25/macOS 在第二轮得到 partial：直接进程探针和一次实际 HTTP 用例采集有效，但 npm/node:test 子进程路由仍出现 Inspector 限制。后续修补未能调试，工作流正确停在 repair_parked，没有据旧通过给出新通过。不继续为此单一工具链扩展通用语言分支或强行关闭覆盖率；保留为重要可用性限制。

不作为产品缺陷：首次 Linux 测试容器的准备脚本沿用了镜像默认普通用户，无法向 `/opt` 写入。已只在容器初始化中使用管理员权限建立目录，再以普通用户执行 SKILL 和原生 Agent；不改变镜像或宿主用户权限。

初步取舍：分析产物中的措辞精简、示例机器版本写入知识候选等先按可读性/宿主发布知识审查处理，不为没有误导结果的偏好扩展新门禁。后续若发现它们导致实际重建错误，再按用户影响升级。

测试过程中的环境/调用问题单独保留，不改写成 Agent 业务缺陷：UI 首次探针把验收资料所在目录当作隔离源码，确定性门禁拒绝未绑定文件，改为独立克隆后重测；覆盖率串联首次用了旧定义绑定，门禁拒绝，宿主用当前绑定新建 catalog 后重测；独立 Node legacy provider 探针缺少其专用 prepared 参数/依赖，属于调用不适用，未计为当前 v4 回归。Linux 并发回归期间出现一次 xstate 暂不可用和一次配置读取失败，隔离重测通过，根因未证实，不能据此声称并发安装稳定性已经充分验证。

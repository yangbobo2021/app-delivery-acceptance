# Agent 可移植性与质量验收

目标：让其他人在符合声明前提的电脑上，获得有依据、可理解、可复现的验收结果。流程能执行、格式正确和命令成功只是基本条件，不能代替职责质量。

本轮范围：当前 v4 主流程，以及仍被文档路由到的 v3 原始需求分析、白盒逆向和必要人工路径。实测使用 macOS ARM64 本机与独立 Linux ARM64 容器。用户已确认其他系统明确标为未实测；原生 Windows 目前也不在 SKILL 声明支持范围内，不以本轮测试暗示已支持。容器结果不代表所有 Linux 发行版、硬件或桌面环境。

## 职责与质量标准

| 角色 | 给用户的价值 | 需要证明的结果 | 典型不可接受表现 |
| --- | --- | --- | --- |
| 需求整体分析 | 确认本轮目标与范围 | 保留全部原文和 ID；分组只提供上下文；显式保留排除和待决策部分 | 漏需求、偷偷扩大范围、把猜测批准为需求 |
| 白盒逆向 | 找到变更的真实行为影响 | 识别重要直接影响，区分既有需求、独立合同支持和待确认行为，引用真实差异 | 将实现或同次修改的 SPEC 当作自己的正确性依据 |
| 场景生成/修订 | 用合理测试点覆盖需求 | 围绕目标义务、条件和可观察结果；保留不同错误机理；不过度组合；修订保留未受影响的人工作品 | 漏掉重要失败路径、凭空规定业务策略、复制相邻需求、虚称独立审查 |
| 运行环境准备 | 在本机重建可用测试入口 | 真实依赖、可执行文件、轻量 smoke 和新电脑步骤；新 ID 独立建环境，复用知识而非旧机器路径 | 只验证解释器版本、业务断言当 smoke、依赖个人绝对路径、擅改产品 |
| 覆盖率准备 | 让后续执行获得可靠指标 | 成熟专用工具；真实零/非零探针和独立读取一致；实际业务 run/finish/verify/summarize 可用 | 自制分母、空数据变成 100%、拿探针冒充业务覆盖、缺部分仍称完整 |
| 项目操作指南（可选） | 减少后续重复探索 | 从项目事实给出入口、隔离、夹具、变量和未知项；只读 | 把操作约定变成全局业务预期，猜命令或重复安装 |
| 查找已有用例 | 复用真实已有验证 | 读实际条件、操作、参数、helper、替身与断言；保留互补支持、跳过状态和限制 | 标题匹配冒充关联、把 Mock 当真实效果、未执行当作不存在 |
| 用例生成/实现 | 补足场景的必要验证 | 先查找；充分时零改动；缺口才扩展/新增；真实产品路径、独立预期、隔离与实际调试 | 重复制造用例、浅层断言、删除旧断言或修改产品制造通过 |
| 用例评估 | 告知当前用例是否合理、充分、有冗余 | 场景逐义务判断；具体必要缺口、真实贡献和取舍；简洁结构和正确引用 | 只评价代码风格、强迫所有测试 E2E、把可选增强当必需、虚称全覆盖 |
| 差量修复 | 低成本补具体测试缺口 | 保留有效测试与观察；只修反馈相关内容；重新调试；不替用户决定未定合同 | 重写整套测试、修改产品/需求、删必要断言、循环无界 |
| 独立执行复审 | 判断结果是否可信 | 以冻结执行和独立合同区分通过、产品 BUG、测试修复、证据/合同限制；UI 判断需真实像素 | 相信 passed_local、退出 0 即通过、环境故障算产品 BUG、未看图声称视觉通过 |
| v3 人工/无源码条件路径 | 自动化不适用时保留可信边界 | 可执行操作设计；未实际操作则停留待提供证据，不模拟人工通过 | 用脚本或模型想象代替真实操作，补造用例和观察 |

宿主执行、冻结、状态机、归档和恢复不是额外的语义 Agent。它们的交接、版本、互斥和证据检查同样属于整条链路验收，分别保留真实执行与语义判断的证据。

## 场景集合与覆盖方法

不建立角色×语言×操作系统的全量笛卡尔积。先为每个角色选正常样例及能暴露核心错误的对照，再用不同语言、项目类型和隔离环境覆盖假设；根据真实失败补充隐藏样例。预期答案和变异脚本留在模型工作区外，首次运行不提供怀疑问题或修复方案。

| 场景组 | 验收场景 | 判定重点 |
| --- | --- | --- |
| BOOT | 从 Git 导出的独立 SKILL 副本首次安装，路径含空格与中文；新 HOME、无旧 local 环境；重复启动复用 | 真正独立安装和原生模型预检；不借用宿主 node_modules/机器路径，不把缺认证当可用 |
| ANALYSIS | 完整需求与明确排除；仅允许部分字段的需求变更 | 无 ID/原文丢失或擅自扩围，修订权限和语义一致 |
| REVERSE | 有独立合同的变更；同次 SPEC/源码共同变化；不同行为项目与语言 | 真正影响不漏，未知行为不批准，引用可核对 |
| SCENARIOS | CLI 配置优先级与只读；服务重试/状态；Web 交互与视觉；明确许可和模糊合同；增量保留人工作品 | 必要目标完整、不同风险合理拆分、无多余业务策略、未定处显式可见 |
| RUNTIME | Python 库/CLI 与 Node 服务的全新准备；项目根与依赖子目录不同；新 ID 读取共享 recipe；缺必要执行器 | 实际项目入口可用、新环境和知识边界正确；失败具体诚实 |
| COVERAGE | 至少两个项目工具链的零/非零探针、独立工具读取和实际用例执行；缺原生数据/不支持部分 | 无伪造分母或命中，实际链路工作，限制准确且可归档 |
| GUIDE | 不同项目的真实入口、状态隔离及环境变量，包含未确认能力 | 操作事实正确，不运行测试或发明业务合同 |
| FIND/IMPLEMENT | 已有充分、部分支持、完全缺少、名字误导、helper/参数/跳过/Mock 边界，至少两个实际执行语言 | 关联质量和必要新增；保护既有支持，变异验证错误识别能力 |
| EVALUATE | 用例充分、浅层假通过、互补用例和冗余、可选边界不应膨胀成必需 | 判断围绕场景；正反样例均准确，引用/文字可信 |
| REVIEW/REPAIR | 可信通过、真实产品失败、测试过约束、环境失败、浅层通过、缺证据；实际 UI 好/坏/缺图；修复后复审 | 判断责任正确，修复局部且保留证据，不靠删业务断言通过 |
| HANDOFF | 至少两种项目的真实串联；新目录读取归档；知识/源码/工具变化拒绝旧凭据；中断/复用 | 单阶段能工作也能正确交接，不串用旧机器、旧版本或旧阶段证据 |
| MANUAL | v3 人工设计在无真实操作记录时暂停；不能把 Windows 未运行说成支持 | 条件路径无虚构执行，平台边界如实呈现 |

独立只读场景审查补充以下具体反例，作为执行清单的一部分：

- `MODE-01/02`：`discover_only` 找到充分测试但零执行；`existing_only` 缺一个断言仍不修改、不自动修补。
- `INTENT-01/02/03`：同一组已执行受影响、新增未执行、不受影响场景，分别按仅设计、普通复验、完成变更验收检查真实启动范围。
- `JUDGE-01/02`：原文只要求数值正确，分别由测试代码附加格式要求、由生成场景附加业务策略；复审应区分测试修补和场景/合同新版本，均不得误判产品 BUG。
- `CONSUMER-01`：资源或配置形式有效但真实消费方不能使用；非空、格式或状态码断言不能证明目标。
- `STATE-01/02`：旧通过与新版本未复审分开；三个场景仅执行一个时保留完整分母、结果类别互斥，接受风险不算通过。
- `RESUME-01/02`：可计数副作用已发生但收据缺失、原进程仍存活；不得自动重放或另起并发执行。另查双场景业务状态隔离。
- `SHARE-01/02`：移除旧 local 后新目录读归档；缺必要证据时明确缺失。候选测试不冒充正式项目回归。
- `OPTIONAL-01`：显式独立场景审查确实走 v3 Reviewer；不将 v4 内部自查改名。可选回填/历史迁移明确留在本轮未覆盖条件能力。

该审查未读历史结果或 gold、未执行模型/业务测试；结论只评价设计，不作为实现通过证明。复用基础样例和真实链路产物覆盖以上反例，优先避免重复运行。

已完成的历史测试可以作为选例和回归依据，但单独标记原版本、模型、环境和范围，不能冒充本轮跨系统实测。

## 场景自审与复盘

执行前检查每个角色是否有：职责相关的正常路径、足以产生相反判定的具体反例、独立预期、最少输入及可核对观察。检查跨角色交接、真实外部效果与替身边界、异常/清理/未完成状态、项目和操作系统分布；去掉重复但保留不同错误机理。独立前向复核只接收原始目标、职责和候选场景，不提供期待的评分或疑似修复。

每个结果保留：源码 revision/哈希、平台/工具版本、输入、模型与会话、原始回答、实际命令及退出码、语义核对理由、用时、问题影响与复测引用。格式校验、实际运行和语义核对分列，不用关键词、字数或模型自评分替代质量判断。

首轮优先运行高风险的准备、场景和复审反例，以及全链路样例；按发现的问题选择下一轮，不无差别重跑。每个重要缺陷修复后重跑原反例并增加不同项目/语言的保留样例。单轮最初失败和原始回答保留，禁止用最新成功覆盖。

## 问题优先级与投入边界

| 级别 | 用户影响 | 处理 |
| --- | --- | --- |
| P0 | 错误宣布验收通过、漏掉关键违约、伪造/混用证据、越界修改产品或真实数据 | 优先修复并跨样例复测；未解决则不能交付对应能力可信的结论 |
| P1 | 常见受支持环境无法使用、重要 Agent 职责缺失、普遍漏检或严重过度生成、恢复/隔离损坏 | 修复通用原因并验证；必要时准确限制已声明能力 |
| P2 | 少见工具链限制、可绕开的清晰阻断、明显偏慢或阅读不佳但不误导结论 | 衡量影响范围、可替代方案和维护成本，必要时记录限制，不强求全部修复 |
| P3 | 文案偏好、低频无害差异、很难修复且价值很低的边缘情况 | 不阻塞本轮，说明取舍；不因单例添加通用特判 |

一个问题经过两次有依据的修正仍无进展，先复盘级别、共性与替代方案，决定继续、缩小声明或记录限制；不是强行两次终止，也不是无界钻研。缺少平台/凭据/专用硬件时明确未验证，不搭建生产环境或伪装平台结果。

本轮完成条件：全部角色和条件路径有明确覆盖状态；高风险反向场景无未处置的错误通过；受支持平台的代表性真实链路和新电脑启动有证据；重要修复有原失败及复测；剩余问题按影响和成本给出明确取舍。最终结论只覆盖实测矩阵，不宣称任意电脑、任意语言均被证明。

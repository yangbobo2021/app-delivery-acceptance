# Skill 本地交付验收场景（设计稿）

被测对象：本机 `app-delivery-acceptance` Skill 的入口、Playbook 运行流程、台账、检查脚本与证据门禁。

范围：原设计针对当前电脑上的行为验收；本次可选覆盖率增强更新另外验证SLC编译/链接产物与真实状态机分支，其他电脑安装仍未实测。

本清单依据 `SKILL.md`、`playbook/delivery-acceptance.md`、`references/data-model.md` 及本次会话确认的测试原则设计。它尚未通过该 Skill 的 Playbook 入口执行；场景是否充分、结果是否通过，仍需独立复核与运行证据。

## 需求索引

| 需求 | 可验收的承诺 |
| --- | --- |
| R1 | 只接收已确认、带稳定 ID 的需求；需求不完整时给出明确范围或缺口。 |
| R2 | 测试前发现并验证资源，持久保存决策；只有真正缺失且无法自行取得的决策才询问用户。 |
| R3 | 第三方真实集成单独验证；可用 Mock 时用 Mock 完成后续 E2E；不可 Mock 的真实 E2E 需可复用凭证。 |
| R4 | 需求关联黑盒场景，代码分支关联白盒场景；每个场景关联测试用例或具体 AI 检查方法。 |
| R5 | 在确定的版本和环境上执行测试，为每个场景保存可核查的结果与证据。 |
| R6 | 独立复核覆盖与证据；失败、缺失或无法证明时不得输出完整验收通过。 |
| R7 | 台账和运行记录可追溯；需求或场景改变时，不能借用旧运行证据。 |
| R8 | 本地工作流入口能运行；不会递归启动或在同一项目并发启动自身。 |
| R9 | 默认标准验收不采集代码覆盖率；增强仅显式开启，恢复不可改模式，缺证据不得降级，循环有界。 |

## 黑盒场景：从交付承诺出发

| 场景 | 需求 | 操作与预期 | 方法 | 应保留的证据 |
| --- | --- | --- | --- | --- |
| BB-01 | R1 | 输入有稳定 ID 的确认需求；生成需求快照并进入资源检查。 | 完整 Playbook 运行 | 原始需求、台账快照、会话轨迹 |
| BB-02 | R1 | 输入缺失或歧义需求；指出具体缺口，不自行批准需求，不宣称完整验收。 | AI 操作检查 | 输入、提问或不完整结论 |
| BB-03 | R2 | 提供已验证的本地依赖决策；下一次运行复用并重新验证有效性，不重复要求用户点击。 | 两次完整运行 | 两次资源台账、验证记录、会话轨迹 |
| BB-04 | R2 | 故意缺少只能由用户提供的凭证或业务决策；仅提出具体问题，回答后续跑并保存决策。 | AI 操作检查 | 暂停、回复、续跑和持久化记录 |
| BB-05 | R3 | 配置可 Mock 的第三方服务；真实集成单独测试，后续完整流程使用 Mock。 | 模拟服务与完整运行 | 真实适配器测试日志、Mock E2E 日志、资源决策 |
| BB-06 | R3 | 配置不可 Mock 且凭证可复用的服务；允许真实 E2E；凭证不可复用时保持阻断。 | 两组资源输入 | 决策及检查脚本结果，不含凭证值 |
| BB-07 | R4 | 现有测试用例只覆盖部分需求；补齐正常、异常、边界路径，并为无现成用例的场景定义 AI 操作方法。 | 现有模拟项目 | 需求、场景、方法三者关联与复核理由 |
| BB-08 | R5 | 运行有用例及无用例的场景；每个结果包含版本、环境、实际观察与可打开的证据。 | 完整运行 | run.json、日志或截图、应用响应 |
| BB-09 | R6 | 一个场景的实际行为失败，或因工具不可操作而未证明；最终不得给出完整通过。 | 故障注入与 AI 操作检查 | 失败/阻断结果、复核意见、最终报告 |
| BB-10 | R6 | 故意遗漏一个场景或其证据；门禁拒绝通过并指出缺项，补齐后重新检查。 | 检查脚本及完整运行 | 失败和修复后的门禁报告、对应证据 |
| BB-11 | R7 | 更改确认需求或场景定义后再次检查旧运行；旧证据失效，新运行才可支持新结论。 | 变更台账后检查 | 新旧哈希、阻断报告、新运行记录 |
| BB-12 | R8 | 在本地 Git 项目调用入口，完成一个端到端会话；对递归启动和同项目并发启动给出明确拒绝。 | 入口脚本及完整运行 | 命令退出码、会话 ID、运行轨迹 |

| BB-13 | R9 | 省略模式、存在旧或畸形覆盖率档案；仍执行标准验收，未调用任何增强角色或增强门禁。 | 入口与真实状态机探针 | 所选模式、角色调用序、五门禁 |
| BB-14 | R9 | 显式增强模式发现重要状态缺口；细化场景后独立复审并建立新full run，最终无必要建议。 | 隔离状态机及门禁探针 | 两轮run ID、设计复审、采集与最终六门禁 |
| BB-15 | R9 | 增强缺工具、产品失败或三轮仍有缺口；保持incomplete，不跳过、不自动降级。 | 负向状态机与检查脚本 | 精确受阻范围、终态、唯一run计数 |
| BB-16 | R9 | 续跑省略模式继承已选值；试图切换、黑盒设计开启增强被入口拒绝。 | 入口隔离测试 | 原/续配置、拒绝退出码、无角色运行 |

## 白盒场景：从当前实现的分支出发

| 场景 | 需求 | 目标分支或状态转移 | 方法 | 应保留的证据 |
| --- | --- | --- | --- | --- |
| WB-01 | R8 | `run_workflow.py` 对非 Git 项目、未忽略的台账、缺少需求文件、递归调用分别拒绝。 | 脚本测试与边界输入 | 各输入、退出码与错误信息 |
| WB-02 | R8 | 同项目锁冲突拒绝第二个会话；正常释放后允许启动。 | 并发操作检查 | 两个进程的结果和锁释放记录 |
| WB-03 | R3 | `playbook.py` 的第三方 `mock`、`real`、`blocked` 分支及真实集成版本/证据校验。 | 参数化脚本测试 | 每组资源输入和门禁输出 |
| WB-04 | R4 | 未知需求 ID、未知方法 ID、缺少白盒目标条件、重复场景 ID 均阻断场景门禁。 | 参数化脚本测试 | 各输入和精确错误 |
| WB-05 | R5/R7 | `new-run` 后台账文件哈希变化、依赖未逐次检查、结果重复或缺失时阻断执行门禁。 | 参数化脚本测试 | 运行快照和门禁输出 |
| WB-06 | R6 | `review.json` 缺少版本、需求覆盖、白盒依据或逐场景证据引用时阻断复核门禁。 | 参数化脚本测试 | 各缺项输入和门禁输出 |
| WB-07 | R6 | `scenarioReview` 只有在覆盖复核和前三道脚本门禁均通过时才进入 `executionRun`；缺口进入修复或不完整结论。 | 状态机测试及 Playbook 轨迹 | 状态转移、脚本原始结果 |
| WB-08 | R6 | `executionReview` 只有在逐场景证据充分且五道脚本门禁均通过时才进入完整结论；失败进入修复或不完整结论。 | 状态机测试及 Playbook 轨迹 | 状态转移、脚本原始结果、最终结论 |
| WB-09 | R6 | 复核角色错误声称通过、但脚本实际失败；完整验收仍必须被阻止。 | 对抗性注入 | 原始退出码、角色答复、最终状态 |
| WB-10 | R5/R6 | 修复台账或产品后启动新的 run ID，并重跑受影响的完整场景；旧运行不被改写成成功。 | 故障修复后的完整运行 | 前后两个运行记录、版本与证据 |
| WB-11 | R6 | 失败终态只引用触发该终态的 run 和证据；收尾阶段不得再创建 run 或把不同 run 的结论拼接。 | 对抗状态机探针及完整 Playbook 失败运行 | 状态转移、最终输出、run ID 与验收目录前后快照 |
| WB-12 | R9 | 角色回包和Boss续答不能覆盖host-owned模式；覆盖率采集中问答重入同run只计一次。 | 真实FSM独立探针 | 模式、coverageRounds、调用序及3唯一run |
| WB-13 | R9/R7 | 原始计数/原源码SHA/测量SHA/台账不匹配，counter deficit未逐项处置或有必要建议时阻断。 | 参数化校验测试 | 每组变更、精确门禁错误 |
| WB-14 | R9 | 标准run不读取可选报告，增强run即使显式请求standard也不能绕过增强门禁。 | 实际脚本负控 | 五/六门禁、畸形报告忽略、降级阻断 |
| WB-15 | R9/R6 | 覆盖率Reviewer虚称sufficient而脚本失败，修复两次后三轮上限终止且不借用旧发现。 | 真实FSM反事实探针 | 脚本退出码、重新设计/新run及终态report路径 |
| WB-16 | R9/R6 | 原发布版实际暂停快照恢复后，补齐标准模式和新字段，保留旧计数和门禁，不进入覆盖率分支；继续执行正常验收。 | 旧FSM生成真实快照、更新FSM恢复 | 原快照SHA、续答、状态序列和完整终态 |

## 验收判定

每个场景都要关联实际执行方法、结果、原始证据与独立复核意见。`playbook.py check` 的结构性通过和 AI 对行为及证据的实质判断必须同时成立。本文件只定义场景，不作为通过证明；本机模拟项目的执行结果和方法边界见 [复验报告](../../../acceptance-simulated-app/.delivery-acceptance/skill-self-acceptance-20260930/acceptance-report.md)。

# 追踪关系视图合同

追踪表是从需求出发的状态地图：建立需求、场景、用例、执行与确认结论的关系，暴露值得关注的问题，并提供核对入口。表格不承担完整报告、日志阅读或所有疑问的解释；详情提供准确编号和复制追问上下文，复杂分析可继续通过 Codex 对话进行。查看器只读，不启动查找、生成、评估、执行或修复。

## 五列与阅读单位

保留 **需求／规则 → 测试场景 → 用例／操作 → 实际执行 → 独立结论**。每个场景一条主行，需求单元格跨场景分组；多个用例列在同一场景下，多次执行进入执行详情。共享用例保留各场景上下文，不按标题跨场景去重。无场景需求仍可见，独立场景不虚构上层需求，逆向规则保留身份及待确认状态。代码覆盖率继续在原有独立面板展示。

| 列 | 默认信息 | 详情责任 |
| --- | --- | --- |
| 需求／规则 | 可读标题、编号、来源身份、场景数、已执行和最近确认通过场景数 | 简短说明、全部场景、原始约定与来源版本；场景通过数不代表需求完整验收 |
| 测试场景 | 重要程度、可读标题、编号、真实存在的当前活动 | 完整条件、操作、预期、视觉要求、所属需求与用例、来源和定义版本 |
| 用例／操作 | 关联数量、前三项可读标题、全部用例入口、设计评价和结构化必要缺口数 | 实际方法、断言、边界；整组设计的充分性、质量和冗余评价 |
| 实际执行 | 是否有真实执行、最近记录时间、执行记录数 | 原始尝试及逐执行项与用例的对应关系、机器结果、历史和证据 |
| 独立结论 | 最近确认结论、当前适用性、重要问题的简短原因及已有 UI 核验状态 | 确认理由、实际依据的尝试和证据、来源版本及风险接受依据 |

标题使用页面及用户语言，自然说明业务对象、必要条件和实际结果；遵循 [用例说明合同](case-display-contract.md)。表格不默认放需求长摘要、文件路径、命令、哈希、Agent 过程术语或 catalog 等原始阶段名。点击对象名称或状态查看内容。

## 状态可信性

设计评价、实际执行、正式结论和版本适用性分别呈现，不压成一个总状态。原定义、执行回执、独立评价和确认判定各自仍是事实来源。

- 关联用例即使未执行也能阅读。生成代码、找到用例和设计支持充分都不算执行或通过。
- 设计评价使用“支持充分／部分支持／存在缺口／无法判断”。未评估、关闭、不可用和过期明确区分。必要缺口只计结构化 `findings.kind=gap`；不从长文临时提取或把增强建议、限制当必要缺口。
- 执行列显示实际事实。组合命令只有组级结果时保留组级结果，不按标题、位置或文件猜测逐用例执行。只有稳定标识的明确绑定才能呈现逐项对应；未提供的对应关系如实说明。
- 尚未执行且无确认记录时，结论列是“尚无结论”；执行后无确认是“等待确认”。机器退出成功不生成正式通过。
- 原确认结论按既有统计合同保留，重跑或准备不清空。详情区分最近执行与结论实际依据的执行。产品 BUG、用例需修复、受阻、证据不足和明确接受风险不能混同。
- 定义失配或已确认结果的代码版本与最新执行版本不同，标注“待重新验证”。定义相同只说明“与当前定义一致”，不推断新产品版本已通过。未知适用性明确显示未核对。
- 未执行、未评估和无结论使用中性表达；提醒和错误状态同时有明确文字，不只依赖颜色。
- 全量统计沿用 [统计合同](project-state-statistics.md)。筛选不改变分母；完整清单缺失时停用整体比例，需求行只描述已发现记录。

## 同一详情交互

所有对象使用现有宽弹窗，小屏全屏，统一 **概览／关联关系／依据与记录** 三个标签。顶部只有上下文路径、对象标题、编号和关闭；不放固定抽样提示。

概览解释当前对象；关联关系列出可跳转的直接关联；依据与记录保留原文、源码引用、实际执行和确认来源。长原文按段落、列表及代码显示，原始对象 JSON 仅按需展开。原代码标题及文件位置留在依据层。无依据、字段缺失和原始证据不可读取都明确披露。

关联跳转在同一个弹窗替换内容，提供返回并恢复标签、展开引用和阅读位置，不叠加弹窗。关闭、Esc 或遮罩关闭恢复表格纵横滚动与入口焦点；支持键盘标签切换，引用跳转聚焦实际摘录。

复制追问上下文仅复制 AT、对象及关联编号、标题和已有状态，不发送消息，不包含完整日志或凭据。

## 关联说明归位

表格没有单独的“关联说明（查找阶段）”流程入口。逐用例明确关联原因放用例详情；只有组级依据时放场景关联关系并标为用例组依据，不能伪装成逐用例判断。检索范围与限制在场景依据中按需查看。设计缺口和冗余统一在独立设计评价中阅读；未执行事实由执行列负责。生成和查找使用相同的用户阅读方式，不以内部角色创建不同界面。

## 浏览与刷新

搜索名称和编号，保留命中的整条关系与父需求；需求命中时保留其全部场景。状态和重要程度筛选明确显示匹配数和总数，父需求统计仍是完整集合。需求可折叠和定位；折叠不隐藏总数，打开需求详情仍可访问全部场景。

表头固定，窄屏横向滚动限制在表格容器内，页面控件可见。定位需求提供窄屏入口。详情正文独立滚动，关闭和追问操作可见。

五秒刷新保留搜索、筛选、折叠及正在阅读的详情。详情使用打开时的记录快照，有变化提示“有更新，查看最新”，用户主动更新，不静默替换正文。同一验收读取失败时保留最后成功快照和读取时间并提示失败；切换验收 ID 则关闭旧详情、清空旧数据与筛选，禁止混入上一验收的记录。

## 实现与验证

`scripts/v3/viewer/traceability.js`、`.css`、`.html` 随 Skill 分发，并由现有 Python 查看器嵌入，无额外前端安装或外部资源依赖。项目状态投影附加只读 `execution_history` 和 `judgment_record`，供详情读取原尝试及其绑定；不改变统计、选择、判定或冻结记录。

验证重点为共享用例的场景上下文、筛选后的完整关联、生成与查找一致性、无执行和待确认、历史确认后重跑、版本变化、组合入口不能推断逐项结果、正确引用、刷新与切换，以及键盘和窄屏交互。视图检查不需要运行被测项目业务用例。

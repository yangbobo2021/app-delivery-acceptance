# 场景用例查找与复用标准

先查看项目自己的目录、清单、运行入口和收集规则，再按行为、调用入口和领域概念定位候选。目录提示不是封闭白名单；有跨模块、组件或其他测试层次的线索时继续跟踪。没有命中场景原词时，沿产品入口及测试调用继续查找。根据项目实际语言和框架理解代码，不要求某种扩展名、测试名、断言库、目录或运行器。

关联依据是实际的条件、操作和观察断言。读取必要的 helper、Fixture、参数表、Mock 与被测调用，分清真实效果与替身调用检查。参数化测试按实际输入和断言说明贡献，可合并为一个带参数范围说明的测试项；不虚构运行时展开名。保留验证不同场景行为的互补用例；不为凑数量选入只含相同词的文案测试、产品实现、文档示例或未实现的占位项。有真实场景断言但默认跳过的测试仍是已找到的关联，标为 skipped，简述默认入口的跳过行为和已有显式运行方式/限制；条件启用测试标为 conditional。关联性与是否执行分开，不能把“默认未执行”写成“没有对应测试”。未实现的跳过占位项仍排除。弱断言可作为有限关联，但不得把未检查的结果写成已经验证；若强用例已有同一贡献，可以不重复选择弱用例。查找阶段不以独立评估结论为前提移除真正互补的测试。

生成与查找 Agent 共用这些标准。先复用项目准备提供的入口和已有有效查找记录，围绕当前场景定向检索；线索不足再沿调用和其他测试层次扩展。一个清楚的小场景不必反复全仓扫描，也不默认另开查找会话。检索受限时说明实际范围与不确定性，不能把没有命中当作项目不存在测试。

# 生成前复用的验证方法

目标是检查默认实现 Agent 是否先发现真实已有支持、只补必要缺口，并避免重复制造测试。结构核验不能代替源码阅读或实际执行。

## 确定性回归

在 Skill 根目录运行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s playbook/v4 -p 'test_case_reuse.py'
```

覆盖启动原文保存、干净文件延迟读取、修改前 checkpoint、真实来源身份、复用正文不变、新项来源、目标引用，以及找到但未采用项不能无理由消失。查找与评估契约、策略和 SDK 访问回归仍需按修改范围运行。

## 原生 Agent 前向验证

使用调用者当前实际 Agent、模型、努力级别和服务，不为测试自行换模型。沿用 Skill 的运行时解析和原生预检。显式环境中已有相应 `ACCEPTANCE_*` 值后运行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/run_case_reuse_forward.py --output /absolute/new-result-directory
```

脚本建立独立验收与工作区，通过真实默认实现入口运行；场景输入不提供“应复用/应新增”的答案。预期与变异逻辑保留在工作区外的宿主中。

| 样例 | 应检查的行为 |
| --- | --- |
| accounts-a | 找到 helper/参数化及拒绝路径的互补断言；直接复用，零测试改动；排除文字匹配和未实现占位项，说明重复弱断言的取舍。 |
| accounts-b | 找到现有成功与拒绝测试；保留支持，只补拒绝后状态保持的必要缺口。 |
| settings-a | 文档计划不能算实际测试；没有关联时创建可执行测试，核验更新值及其他已有项。 |
| accounts-c | 项目只有成功路径测试时，保留它并新增缺失的独立拒绝路径，避免重写成功用例。 |
| web-session-a | 使用项目的 JavaScript 入口，保留注销状态与清除 Cookie 的互补验证。 |
| preview-a | 使用项目的 Shell 入口，找到路径输出及不创建文件的实际断言。 |

读取 `results.json`、原始 `answer.json`、checkpoint、实际测试及 Git 改动。确认每个最终用例的贡献与来源准确；补充、新增理由要对应当前场景，不能用仅通过命令证明质量。尤其检查没有因当前场景未提及而删除原有断言，没有为日志、文案偏好或无必要的整理改写充分的测试。宿主独立重跑最终业务命令；还将产品分别改为“拒绝时扣款”“更新时清空其他项”“未删除会话”“未清除 Cookie”或“预览时创建文件”，检查返回的真实用例是否识别错误。阅读失败日志，排除环境故障造成的假阳性。产品源码保持原样，变异只发生于独立副本。

记录模型运行时间、工具调用和会话原文，核对每个场景仍只有一个实现会话，checkpoint 是确定性宿主操作。总时长包含搜索、写入、调试与回答，不能当作新增开销；没有修改前对照数据时不宣称加速比例。小样例通过不证明大型项目检索完整，后续扩充项目和隐藏样例时继续使用同一语义标准，不向生产实现加入语言或项目特判。

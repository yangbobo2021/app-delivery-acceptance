# 覆盖率专用工具执行规约（强制）

适用于 v3、v4、覆盖率采集、仅补采/离线重算、覆盖率增强及结果展示。准备、用例实现、差量修复、证据处理和复审入口必须携带本规约；不能依赖执行 Agent 自行查阅主 SKILL。用户明确限定不重跑、不复审或不扩大范围时，继续遵守该限制；补齐工具不能成为擅自执行新业务操作的理由。

## 持续采集入口与程序门禁

新项目和重新采集的旧用例必须走同一流程：**冻结源码与完整范围 → 选择并验证专用工具链 → 工具生成完整零命中分母 → 每场景执行并保存原始报告 → 程序验证 → 专用模块合并/汇总 → 更新视图**。不把每次补采做成不同的临时脚本链路。

工具选择、依赖锁定、配置、夹具和调用适配由项目准备阶段根据实际语言、框架和运行方式生成，保存在项目测试树及项目知识中。通用 Skill 不设置语言/provider 白名单，不因缺少内置实现就结束项目准备。无法采集时记录实际尝试及具体缺口。

- 新准备使用语言无关的 `project-coverage-v1` 协议；manifest、操作和报告格式见[项目覆盖率准备协议](project-coverage-protocol.md)。项目入口提供 `verify-preparation / run / finish / verify-report / summarize`，由所选成熟工具完成全部覆盖率计算。只交汇总 JSON 或工具标签不能成为 `measured`。
- 项目 catalog 保存 `{policy:"required",protocol:"project-coverage-v1",prepared:"绝对准备目录",prepared_sha256:"manifest摘要",inventory_path:"冻结范围清单"}`。准备验证工具版本、真实探针、完整源码处置和工具生成的零命中单位，再激活持续索引。工具、配置、源码、适配器或统计范围改变都使用新准备/catalog；先结束仍使用旧准备的活动执行，保留旧资料。
- prep spec 的 `coverage_test_files` 声明项目内适配器与必要夹具，宿主冻结哈希并自动绑定到场景、本地调试和正式执行。统一入口为 `run_evidence_v2.py --coverage-config <配置>`；直接补采使用同一个 `run_coverage.py`，不能另写识别/统计链路。已激活配置不能由旧模板降级或替换。
- 通用程序验证项目目录、完整源范围、场景/版本/准备关联、真实执行会话/收据、工具来源及所有冻结证据字节；统计与合并仍调用项目专用工具。输出、fresh dirs 及目录环境变量须在本 ID workflows 内，实际执行使用唯一验收 workspace。独立合成探针不能冒充业务执行或绕过验收绑定。
- 按进程/页面文档保留独立快照，累计快照更新同一对象；不得反复相加或把上一场景计数归到下一场景。失败用例的可靠原始计数仍可登记，覆盖率不会改变独立业务结论。收尾错误、强制终止和缺失数据如实标 `incomplete/unavailable`。
- `coverage_registry.py` 保存不可变采集条目，同一准备按场景选最新有效采集，兼容报告由项目工具合并。登记失败可以对同一冻结报告重试，不为刷新视图重跑业务。混合语言分别显示组件的原生行/分支口径；无法可靠合并时不制造统一百分比。
- 覆盖率专用归档使用公开 `archive --coverage-report` 配置，保留原生报告、收据、会话、准备、范围及冻结源码/适配器；按同哈希路径映射读取，不改写历史证据。视图每次核验绑定及实际工具版本，缓存不得掩盖证据或工具变化。

旧 `istanbul-source-v1` 实现保留为明确的 legacy 兼容入口，服务于既有准备和历史证据；它不是新项目的固定技术栈或工具注册要求。准备验证只证明工具能力，不表示业务场景已通过。

## 工具选择与职责边界

- 必须选择与实际语言、编译链和运行时相匹配的成熟专用覆盖率工具及其正式支持的模块/API。多语言项目分别使用对应工具，保留各自分支口径；不强行用一种语言的定义处理另一种语言。
- 行/语句识别、分支与嵌套分支识别、零命中分母、命中判定、源码映射、编译辅助代码处理、计数合并和指标汇总，必须由专用工具支持的流程完成。工具名称不是背书；必须验证实际执行、版本、配置和输入兼容性。
- **禁止自行实现或替代上述覆盖率算法**：包括自写 AST/正则扫描构造分母、自定义分支出口/ID 后匹配计数、从 V8 范围自行反推分支命中、手写 `??`/可选链/转译辅助条件的语义还原、拼接不同基线、补造零计数、手工合并不兼容分支或猜测百分比。不得复制/修改专用工具内部函数再包装成“使用官方工具”。范围选择后的跨文件计数和汇总也使用工具生成的统计，不以适配器自行累加逐文件计数替代工具汇总。
- 项目适配代码只可调用工具、传递配置、执行命令、规范化文件路径/报告格式、绑定证据和展示结果。范围筛选必须基于工具输出的原始源码位置/单位；筛选后使用工具正式支持的统计接口或报告流程重算。不自行重新识别分支或改写计数语义。通用格式解析器可读取工具报告，但不能生成工具未给出的覆盖率单位或计数。
- 例如，JS/TS 可以使用 V8 专用转换模块与 Istanbul 官方覆盖率合并/汇总模块；Python 可以使用 coverage.py 的分支能力；Java 可以使用 JaCoCo。例子不是跨项目固定技术栈。原始计数不足、缺少必要源码映射或工具不支持当前编译产物时，保留真实资料并记录缺口，不能靠自制还原器绕过。

## 准备、执行与证据

1. 项目准备记录语言/运行时、实际采集器、转换/源码映射模块、合并/统计模块，以及各自的名称、准确版本、实际命令或 API、配置、支持的指标与官方文档依据。仅找到安装包不代表采集链路已成立；无法确认的版本写“未记录/未知”，不得猜测。
2. 冻结与所选用例绑定的原始计数、原始工具报告、工具链配置/调用及源码/映射文件哈希。未执行源码的零命中单位也须来自工具支持的完整分母生成方式。行和分支分别声明 `measured`、`incomplete`、`unavailable` 或 `off`，不能用行报告冒充分支报告。
3. 合并前核对源码版本/字节、采集与转换设置、工具版本及分母兼容性；兼容性必须有工具或配置依据，不能仅凭路径相同。不同源码版本、不同口径或不兼容报告不能强行相加。场景通过、失败、接受风险和证据不足均不改变真实计数是否可用；独立验收结论另行保留。
4. 仅重算时只能读取已有原始资料、使用工具支持的转换/合并/报告能力并生成新的处理记录，不重新执行用例或业务操作。旧证据保持不变。缺计数与确认未命中必须区分；不可靠部分不得按零覆盖或“无分支”处理。
5. 发布数值前核对专用工具实际调用、报告来源、完整/缺失范围和版本兼容性。只写工具名称或提供一个看似合理的百分比不满足规约。自制覆盖率算法的结果不能标为合规 `measured`，也不能因改名或添加工具标签而升级。旧报告缺少这条证据链时保留原状并注明未按当前规约验证；不得追补虚假工具来源。

## 展示与范围切换

- 默认分别展示行覆盖率、分支覆盖率，注明对应覆盖数/总数与必要的缺口；不把未知值显示为 0%。只有工具数据支持的指标才显示实测百分比。完整范围不足时明确标注，不能把已测部分称为全项目结果。
- 在覆盖率区域直接显示简洁的工具信息：**采集工具及版本 → 转换/源码映射工具及版本（如有）→ 合并/统计工具及版本**。可展开查看实际命令/API、配置及证据。不同指标或组件使用不同工具时分别注明；缺少的环节/版本直说，不将某个转换器名称冒充整条统计链路。
- 切换整个项目、修改文件、修改行等已声明范围时，对行与分支同步筛选并重算分子和分母。修改行的分支归属使用已冻结规则及工具提供的源码位置；工具无法支持该精度时标明不可计算，不自写语义分析器补齐。
- 项目编号、提交号和原始文件清单留在证据元数据；无需用它们代替用户关心的指标与工具信息。工具能力或格式缺口不授权扩大场景集合、重跑真实副作用或声称业务验收通过。


## 历史证据的目录迁移

按项目存储规约显式迁移时，保留原报告/收据的字节、哈希、时间和采集版本。已冻结绝对路径用只读证据路径适配器映射到新目录内的同哈希文件；未映射旧依赖禁止回退读取。适配器只转换读取路径和目录列举，统计仍由未改写的专用 provider 和对应语言工具完成。不得为了迁移重写工具指纹、计数或冻结报告；无法取得兼容工具或完整原始依赖则如实标明缺口。覆盖率展示同时列出实际统计工具与路径映射适配器，业务结论版本与采集版本分别保留。参考 [项目迁移规约](project-acceptance-store.md#真实旧资料迁移规约)。

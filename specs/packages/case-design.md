# case-design: 已有用例查找、复用与补充

## 意图

为当前场景采用足以验证其判据的实际用例组，优先利用已有测试并避免制造冗余。

本包规定需求目标，不声明当前实现已经符合或通过验收。

## 外部行为

### case-design-1

当以默认实现策略处理一个场景时，用例 AGENT 应在同一连续会话中先查找适用的已有测试，再按场景缺口选择复用、扩展或新建，不默认串行运行一次完整的独立查找会话。

### case-design-2

当查找当前场景的关联测试时，查找过程应依据实际条件、输入参数、操作、断言、辅助实现及替身边界说明用例对场景的贡献，不仅按标题、同段代码覆盖或历史通过建立关联。

### case-design-3

当默认实现策略准备修改测试或开始调试时，宿主应先核对并保存修改前的实际关联、源码引用和文件基线，缺少有效检查点时不接受后续复用决策为就绪结果。

### case-design-4

当已有测试已支持场景全部必达判据且没有已证实的运行或证据问题时，用例 AGENT 应直接复用，保留业务正文及有效断言，不为标题、日志或无关整理修改已有测试。

### case-design-5

当已有用例只支持场景部分必达判据时，用例 AGENT 应保留有效贡献，仅为缺少的输入条件、操作或结果核验扩展断言或新增互补测试，并逐项记录缺口及所作选择。

### case-design-6

当编写新的测试断言时，用例 AGENT 应以冻结约定为预期依据，并说明输入和观察能够识别的具体错误行为，不从当前实现推导额外业务义务。

- 生成、查找、独立评估及执行复审的场景输入应保留冻结的完整执行背景及共享约束，不能仅保留目标、业务目标和范围摘要。宿主应拒绝缺失或篡改的非空执行背景；这些背景用于正确理解当前目标，不将相邻需求自动扩成执行范围。

### case-design-7

当多个候选输入针对相同测试目的时，用例设计应说明所选代表输入及必要边界，并将新增组合限定为能区分场景所要求的不同错误行为。

### case-design-8

当场景判据不能可靠机械判定时，用例实现应保留该次实际观察、采用的替身及未贯通部分，交由独立复审判断 [[execution-evidence-5](execution-evidence.md#execution-evidence-5)]，不把关键词命中或替身调用写成完整业务结果。

- 角色操作说明应准确指向实际完成标记、退出回执及合并日志，区分本地调试完成与宿主尚未作产品判定 [DR-024](../decisions/024-debug-receipt-prompt.md)。
- 本地调试事实应由统一入口完成标记及其实际命令、日志和所需覆盖率收尾证据支持；包装命令成功不能替代完整调试。计数区分开始的尝试、已完成的调试及未完成项，不将嵌套传输回执重复记为业务执行。

### case-design-9

当用户选择仅使用已有用例的策略时，查找 AGENT 应读取并选择既有测试，通过既有入口调试，不新增、修改或删除测试、产品、SPEC及配置；宿主校验的 ID 注释补丁仅按身份规则允许 [[case-identity-4](case-identity.md#case-identity-4)]。

### case-design-10

当用户选择纯静态关联模式时，查找流程应只保存实际检索范围、关联和限制，并标记为未执行，保持执行观察为空，不运行测试、构建或应用。

### case-design-11

当生成、查找或修复 AGENT 提交用例说明时，说明应以相同字段记录实际方法、断言、验证边界和源码位置，缺失信息留空并标注，不能用场景预期补造已有能力。

### case-design-12

当交付验收中新建或扩展的测试代码时，用例 AGENT 应沿用项目既有测试目录、框架、夹具和回归入口，尚未实际集成的代码须明确标为候选测试。

### case-design-13

当生成、查找或修复 AGENT 提供展示标题时，用例标题应使用用户与页面一致的语言，说明业务对象、区分相邻用例所需的条件和实际检查的行为或结果，不以代码步骤堆砌或夸大断言能力。

### case-design-14

当关联跳过、条件启用或运行状态不明的已有测试时，查找结果应保留其实际贡献并标明可运行状态、启用条件或未知原因，不把它记成不存在或默认已经运行。

### case-design-15

当最终采用的用例集合与修改前检查点不同 [[case-design-3](#case-design-3)] 时，用例 AGENT 应对每个最终用例记录复用、扩展或新建的来源及理由，并说明检查点中已关联但最终未采用业务用例的原因，不把已排除候选文件当作关联用例；最终提交只缺固定协议标记时，可在原会话最多请求一次不执行工具的结构补正，保留原答并拒绝其他内容变化。

### case-design-16

当宿主接收查找或复用关联结果时，宿主应核对当前场景义务、双向用例关系、真实文件及声明、连续源码引文和版本哈希，引用或身份失配时拒绝该结果作为就绪关联；同一会话可在提交前调用相同规则的只读预检，最终提交仍重新核验。

### case-design-17

当已有断言不属于当前场景时，用例 AGENT 应保留该断言，除非存在独立合同依据证明其错误并记录修正影响，不将“本场景未要求”作为删除或放宽已有断言的理由。

### case-design-20

当调用者针对用例准备或已证实的问题提出具体操作要求时，入口应将该要求原样保存并交给用例角色，不依赖角色读取宿主对话，也不将操作要求扩成新的业务判据。

### case-design-21

当冻结的 `context.user_constraints` 非空时，当前用例、查找、独立评估与执行复审应逐字接收该操作约束，缺失、压缩或篡改即拒绝交接，但不因此新增场景义务或将纯调度说明变化机械等同于全量重测。

## 验证

以下分别登记静态查找及动态准备的集成验证，不代表全部项目组合已通过。
历史测试报告不作为本包当前需求已经通过的证明。

### case-design-18

当验证独立静态查找入口时，集成测试应通过真实官方 CLI 的 Finder 调用核对实际断言关联 [[case-design-2](#case-design-2)]、未执行状态 [[case-design-10](#case-design-10)]、跳过项的真实状态 [[case-design-14](#case-design-14)] 及宿主引用门禁 [[case-design-16](#case-design-16)]，并通过另一角色会话验证独立评估可消费最终关联。

### case-design-19

当验证 Node 动态用例准备入口时，集成测试应通过真实官方 CLI 角色及实际调试核对先查找后修改 [[case-design-3](#case-design-3)]、复用或补齐缺口 [[case-design-4](#case-design-4)]、已有用例策略的文件保护和真实调试 [[case-design-9](#case-design-9)]、逐项取舍及原声明身份 [[case-design-15](#case-design-15)]、显式准备要求传递 [[case-design-20](#case-design-20)]、源码引用门禁 [[case-design-16](#case-design-16)]，并用受控错误产品实现验证最终测试能发现对应违约 [acceptance_cases.integration.mjs](../../tests/acceptance_cases.integration.mjs)。


### case-design-22

当验证冻结约束交接时，集成测试应核对原文传递与篡改拒绝 [[case-design-21](#case-design-21)]，并通过真实官方 CLI 检查用例、独立评估和执行复审的实际输入 [full_native_journey.integration.mjs](../../tests/full_native_journey.integration.mjs)。

# case-identity: 永久用例身份

## 意图

通过普通源码注释让实际关联的测试声明在场景、评估、执行和维护中保持可核对的身份。

本包规定需求目标，不声明当前实现已经符合或通过验收。

## 外部行为

### case-identity-1

当本 SKILL 实际采用一个已有或新建测试声明时，宿主应复用其有效源码 ID，缺少标记时分配 TC- 前缀加 UUIDv4 的永久 ID，并在该声明的合法注释位置保存标记 [[case-identity-10](#case-identity-10)]。

### case-identity-2

当同一测试关联多个场景、修改标题、移动文件或补充断言时，维护流程应保留随声明保存的已有 ID，不按场景、路径、标题或执行次数重新编号。

### case-identity-3

当新增一个独立测试声明时，宿主应分配未被其他声明占用的 ID，不复制旧用例的标记，也不把新增声明伪装为已有声明的扩展。

### case-identity-4

当宿主为仅查找策略关联的测试补充 ID 时，文件保护应只允许与启动时字节和权限匹配的精确注释插入补丁，任何业务正文、断言、配置、权限或文件集合变化均阻止交接。

### case-identity-5

当完成源码 ID 补充时，宿主应在正式执行冻结文件之前 [[execution-evidence-2](execution-evidence.md#execution-evidence-2)] 更新最终结果的身份引用、行号和文件哈希，并保留原始 AGENT 回答字节及此前调试证据。

### case-identity-6

给定候选测试尚未集成且当前源码缺少标记，当跨验收复用身份时，宿主应仅在共享索引记录的文件、声明定位、原始标题和测试正文均匹配时沿用原 ID，匹配不确定时报告限制。

### case-identity-7

当发现重复或无效 ID、错位标记、无效源码引用或无法安全定位的声明时，宿主应阻止受影响身份的交接并报告具体文件及原因，不静默合并或批量重编号；提交前注释预检只核验声明及可用注释语法，不分配 ID 或改写源码。

### case-identity-8

当评估或展示使用用例短别名时，产物应保留其到永久 ID 及实际源码声明的对应关系，不将有 ID 或已关联解释为该用例已执行通过。

### case-identity-9

当同一参数化测试声明使用多个运行数据行时，宿主应为该声明保留一个 ID，不按数据行数生成多个独立声明身份。

### case-identity-10

当写入永久 ID 时，宿主应使用包含完整 `@case-id: TC-<UUIDv4>` 的普通单行注释，紧邻完整测试声明之前并位于其装饰器或属性之外，不写入字符串、模板或其他数据内部。

### case-identity-11

当宿主插入 ID 注释时，补丁应保留原有正文、文件编码标记、换行方式、权限和脚本必需文件头，不因注释处理改变测试行为。

### case-identity-12

当完成实际采用用例的身份登记时，宿主应在项目共享 .acceptance/case-identities.json 保存永久 ID、源码绑定及场景关联，登记范围只包含已采用测试，不冒称全项目测试清单。

- 实现模式下，已验证原答对冻结查找检查点的精确回声属于历史检索资料，不把未采用条目转换为当前关联；保留原答及检查点引用，未知或变化的关联仍拒绝。

### case-identity-13

当将身份工具迁移到 Node 时，集成测试应在真实 Git 文件上核对永久 ID 分配及复用 [[case-identity-1](#case-identity-1)]、精确补丁和格式保留 [[case-identity-11](#case-identity-11)]、原答及最终源码绑定 [[case-identity-5](#case-identity-5)]、跨验收索引复用 [[case-identity-6](#case-identity-6)]、历史检索回声与实际采用范围 [[case-identity-12](#case-identity-12)] 和冲突拦截 [[case-identity-7](#case-identity-7)]，实际运行注释后的测试确认行为。

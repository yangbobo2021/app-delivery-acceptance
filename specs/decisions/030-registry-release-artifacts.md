# DR-030: 可直接发布到 Registry 的可追溯产物

## 状态

已接受，依据用户确认采用 Apache-2.0，并按源仓库、分发仓库、包平台的顺序更新。
补充 [DR-025](025-source-and-distribution-repositories.md) 的发布产物和安装说明，修订 [DR-019](019-unified-spex-installation.md) 的资源选择及安装清单生成范围。

## 背景

0.4.16 的 Git 安装通过，但 Registry 发布检查发现许可声明缺失，携带历史依赖归档的压缩包也超过平台的 5 MiB 上限。
本地发布投影补齐许可、排除未引用归档并更新清单后已完成单包安装和最小调用验证，该手工步骤需要回到源码构建中。

## 决策

- 项目与独立运行包声明 Apache-2.0 并携带许可证，第三方许可和来源保持原样。
- 发布 Skill 只携带包清单及依赖锁引用的本地归档，包括锁中的传递引用；缺失或不可移植的引用在输出前拒绝。
- 历史归档保留在开发源码，不改当前依赖、锁定摘要或业务代码以满足体积限制。
- `SPEX-INSTALL.json` 在复制、筛选完成后根据实际发布的运行包自动生成；来源记录仍描述原始源码提交。
- 生成说明优先介绍 Registry 按包名安装，保留 Git 备用入口；构建、仓库更新与真实平台发布仍为独立步骤。
- 用真实 SPEX 发布打包入口检查许可、文件闭包、校验清单和压缩体积，不提高平台限额或裁剪必需资源。

## 影响

不改变工作流、Agent、目录隔离、权限、证据和缓存校验的业务要求。
0.4.16 已发布版本保持不可变，新构建以 0.4.17 关联源提交、分发提交和 Registry 回执；两平台实际运行范围仍单独记录。

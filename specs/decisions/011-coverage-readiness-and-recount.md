# DR-011：固定报告核验与完整准备验证

## 状态

已接受；细化 [DR-010](010-deterministic-coverage-protocol.md) 的项目后端边界，并部分修订其“项目后端负责原生重算及核验”的范围。
原生重算仍由项目工具负责，是否一致的判断由固定协议负责。

## 背景

两轮独立对照分别因用途描述及报告生成时间不同而误拒绝。
此前探针只证明采集及读取能力，没有强制验证最终入口的收尾、核验及汇总。

## 决策

- 新准备采用后端 v2：后端只提供 tools、run、read；同一个 read 操作从一组或多组原生数据调用成熟工具生成指标及范围统计，不分别编写收尾、重算和汇总的统计路径。
- 固定 Node 协议拥有 finish、verify-report、summarize 的会话、证据及响应封装，项目后端不生成这些通用合同。
- 固定 Node 协议验证原文件哈希、工具身份及重算后的源码范围和指标，不比较工具报告的生成时间或展示描述，不自行计算覆盖率。
- 原生数值指标按工具实际能力验证；不强迫不支持的行或分支指标变为实测。没有任何可测源码及路由时只能保留有依据的 partial，不能通过空路由声明 ready。
- 调用者可显式补充本次准备的进程或入口要求，这些要求冻结后完整传递给准备角色；授权依据不代替具体执行要求。
- 激活新准备前，通过最终冻结入口执行每条声明路由的非业务零/非零命令，完成 run、finish、重复 verify-report 和 summarize，保存真实命令及原生证据。
- 汇总验证包含全零、非零及混合数据组合；全零数据仍须保留工具的真实分支模式与分母，不能用字段默认值或自行制造命中单位修补。
- 探针或完整链路失败不发布就绪交接；原生资料缺失或变化、指标变化及后端读取时改写证据仍须拒绝。
- 原历史证据及其冻结入口不改写；本轮仅进行有界短回归，不据此声明完整业务验收通过。

## 影响

项目适配仍按真实工具和进程选型，保留语言无关边界。
已有后端须在新的准备中实现统一 read 及完整路由验证，不通过隐式兼容跳过新门禁。

# DR-016: 子流程输入预检与场景设计就绪边界

## 状态

已接受，依据用户要求：先提交当前状态，再进行适用于不同项目和需求的程序及提示规则修正。
补充 [DR-015](015-playbook-owned-task-orchestration.md) 的子调用准备及设计问题接续边界，其余调度与独立入口职责不变。

## 背景

独立 CLI 验证发现总调度多次漏交冻结字段或来源快照，场景角色也曾因产品尚未实现而拒绝定义已有明确判据的黑盒场景。
最终目标达成不代表每个子调用都准备正确，也不代表总调度临时整理的场景经过设计角色检查。

## 决策

- 子工作流可随注册模块公开只读输入预检及合同说明，总调度动态发现并在官方子调用前使用；预检不得发布定义、创建业务尝试或替代正式入口。
- 预检与正式入口复用同一校验；独立可发现的输入问题集中返回，正式入口仍在互斥及当前版本条件下重新校验，不自动补造业务目标或来源。
- 黑盒场景根据冻结需求的可观察业务判据设计，产品实现、命令、账号、设备或执行环境尚未具备时仅记录后续执行前提；未确认的业务结果仍是设计缺口，白盒源码依据仍须核验。
- 设计结果分别报告义务覆盖完整性、真实缺口和执行前提；合法许可条款可没有场景，不以场景数量或关键词替代语义判断。
- 总调度通过带来源绑定的纠正意见将设计问题交回 Designer；角色原答和失败尝试保留，纠正不改变冻结需求，也不把总调度自写的场景伪装成角色设计。

## 影响

现有 CLI、旧设计回执和单步停止边界继续兼容；新增信息用于更准确地准备输入和解释结果。
只读预检可被状态变化取代，不能作为正式发布授权或免检凭证。

# DR-009: Skill 接入与完整 Playbook 工作流包的职责边界

## 状态

宿主跨工作流选择与接续职责由 [DR-015](015-playbook-owned-task-orchestration.md) 局部修订为总调度 Playbook 所有；独立子工作流其余边界保留。

覆盖率准备的项目输入、内部运行资料准备与自主修复由 [DR-013](013-outcome-owned-coverage-preparation.md) 局部修订；其他业务停止边界不变。

用户已明确目标：切清 Skill 辅助脚本与 Playbook 的边界，任一工作流可由 Playbook 命令完整调用。
已按本边界完成搬迁；独立 npm 安装、标准 CLI 主链路及角色/图片验证通过，范围与限制见[本轮验证记录](../../reviews/skill-playbook-boundary-20261028.md)。
补充 [DR-007](007-complete-native-workflow-migration.md) 与 [DR-008](008-workflow-owned-source-layout.md)；本轮实施职责切分，不恢复此前停止的六项目验收。

## 背景

当前工作流已按业务职责归类，但仍读取 Skill 外层 references 中的运行合同，部分内部角色采用独立环境变量绑定，并依赖自定义 Node 启动适配交接服务、权限或结构化结果。
此前经适配启动器完成的验证不等于脱离 Skill 后通过标准 Playbook CLI 完整执行已获验证。

## 决策

- Skill 是对话接入层：宿主理解完整对话、识别实际授权范围、读取用户提供的来源、保留原文与出处、选择或组合独立工作流，并通过公开 Playbook 命令交接显式输入及解释输出。
- Skill 的辅助脚本仅承担接入与安装便利，例如定位已安装工作流包、检查启动条件或调用其正式安装入口；它们不创建验收业务目录，不冻结定义，不执行用例或业务门禁，也不补写结果和结论。
- Playbook 工作流包拥有完整交付测试业务：创建与当前指针、冻结、分析、逆向、场景、关联或生成用例、独立评估、项目环境和覆盖率准备、执行与修补、恢复、判断、报告、归档和收尾。
- 一个工作流从公开输入开始，到自身声明的成功、失败、等待输入或停止边界结束；运行期间不要求外层 Skill 接着执行内部步骤。跨工作流组合仍允许由宿主依据用户请求灵活选择。
- Playbook 包随附其运行必需的脚本、提示词、标准、合同、注册、配置描述与依赖清单。工作流只依赖本包、公开运行时、明确输入的用户项目资料和已声明的环境能力，不反向依赖 Skill 安装路径、对话、脚本或文档。
- Node 工具可以保留在 Playbook 包内，归属于对应工作流或确有多方调用的共享模块；语言和文件扩展名不决定职责归属。测试执行、证据校验和报告工具均由工作流管理。
- 工作流注册清单、角色声明、配置生成与依赖版本由 Playbook 包维护，Skill 只消费其公开配置合同，不维护第二份角色/工作流清单。
- 模型角色、会话、权限、服务交接和图片/结构化输出通过官方 Playbook/Cligent 的能力及正式支持的扩展管理，工作流声明实际角色与配置；Skill 不另设必需的模型调度或启动补丁链。
- 用户或 CI 可以在没有 Skill 的环境中，安装工作流包并配置真实模型服务后，以标准 Playbook CLI 选择任一公开入口并提供显式输入；普通调用不以自定义 Node 启动包装器代替该入口。
- 当前锁定官方版本存在的服务、权限、图片或结构化输出能力缺口须单独登记并通过正式扩展或运行时实现解决，不以迁移文件位置或保留 Skill 启动器声明独立运行已完成。
- 凭据、真实认证环境、项目语言工具及前序业务产物仍可作为声明的运行前提；独立执行不意味着无认证、无依赖或自动执行前序工作流。缺前提应明确报告，不读取隐藏宿主上下文或扩大授权。

## 当前模块归属

| 当前模块 | 目标职责归属 |
| --- | --- |
| SKILL.md 中的意图识别、来源交接、入口选择、用户沟通 | Skill 接入层 |
| 安装位置发现、调用安装入口等接入便利脚本 | Skill 接入层；独立 Playbook 用户无需执行这些脚本 |
| workflow-config、注册发现、角色清单 | Playbook 包的公开配置能力 |
| package.json、锁文件、依赖安装与核验实现 | Playbook 包；Skill 可调用其安装入口 |
| agent-preflight | Playbook 包或官方运行时的公开能力；Skill 可按需调用 |
| acceptance-guard、case-tool、coverage-tool、coverage-probes、runtime-verify | Playbook 包的工作流内部工具 |
| 角色提示、业务标准、输出合同 | Playbook 包的对应工作流或共享合同 |
| agent-runtime、native-cli-*、opencode-*、official-cli 中的服务与权限适配 | 官方运行时能力/正式扩展或包内合法适配；按实际官方支持迁移，不归入 Skill 的必需启动链 |

## 验收约束

1. 将完整 Playbook 包单独复制或安装到新目录，不安装 Skill，也不保留到 Skill 源码的链接。
2. 检查全部运行资源和动态路径，不允许读取 Skill 的 scripts、references、SKILL.md 或原安装目录。
3. 使用标准 Playbook CLI 加载并逐项调用全部公开工作流，核对每个入口的正常路径、必要前提及明确停止/失败结果；注册成功不是业务成功。
4. 针对需要前序产物的入口先通过公开工作流建立真实前提，再独立调用目标入口；外层不代办该入口的内部业务步骤。
5. 核对实际角色、模型/服务、会话隔离、权限、执行收据、文件与证据哈希以及业务终态，不以 exit 0 或回复文案代替结果。
6. 针对当前启动适配涉及的 Codex、Claude Code、OpenCode 及图像/结构化交接分别保存真实验证范围与缺口。
7. 同一包通过 Skill 接入与人工/CI 直接命令调用时，采用相同输入、业务门禁和结果合同。
8. 所有门禁和修复保持原始失败证据；正常前序数据要求与独立包运行缺口分别记录。

## 影响

Skill 可以随工作流包一起分发，也可以独立接入已安装的包；两者的依赖方向保持单向。
迁移需要同时调整配置归属、包内资源寻址及官方运行时交接能力，不能只搬动 mjs 文件。
在独立安装和标准命令验收完成前，当前适配链的通过记录继续有效，但不扩大为独立包已通过的结论。

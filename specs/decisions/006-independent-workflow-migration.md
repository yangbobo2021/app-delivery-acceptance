# DR-006: 逐个接入独立工作流并验证边界

## 状态

已接受，依据用户授权继续逐个实现、每完成一个充分测试。
兼容路径的最终收敛要求由 [DR-007](007-complete-native-workflow-migration.md) 修订。

## 背景

宿主需要按用户意图选择创建、冻结、设计、查找、评估、执行及恢复等独立过程，不能强制走完整流水线。
现有存储格式、版本哈希、场景修订及执行门禁已有兼容资产，同步重写全部协议会扩大回归范围。

## 决策

- 各独立入口由官方 Playbook CLI 注册加载，宿主显式交接输入和停止位置。
- 确定性过程不增加模型角色；需要模型的过程使用官方运行时角色绑定和会话管理。
- 每个入口分别验证真实 CLI、实际产物、重复请求、前置条件、版本变化及停止边界，通过后继续后续入口。
- 增量冻结默认保留未涉及对象；完整替换必须显式提供替换依据，旧版本不可覆盖。
- 迁移期复用既有 Python 协议校验及存储工具，并在入口说明和回执中声明；不将注册入口完成等同于 Python 依赖已消除。
- 保留旧入口作为兼容路径，未迁移或未实测的能力继续明确标记，不因部分入口完成而宣称全部需求已满足。

## 影响

创建与冻结可分开执行，也可以由宿主顺序调用。
场景设计不会隐式启动用例实现、运行准备或测试执行。
后续 Node 迁移须保持已验证的外部行为及历史格式，或单独明确版本迁移边界。

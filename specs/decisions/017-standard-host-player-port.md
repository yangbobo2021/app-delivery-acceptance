# DR-017: 通过标准宿主角色端口运行工作流

## 状态

已接受，依据用户要求：尽量不修改 SPEX，让同一工作流包在 SPEX UI 和 Codex Skill 下工作；目录、权限和证据规则保留在工作流 Prompt 与校验逻辑中。
局部修订 [DR-009](009-skill-playbook-responsibility-boundary.md) 的运行时能力适配边界；[DR-015](015-playbook-owned-task-orchestration.md) 的总调度所有权不变。

## 背景

CLI 的固定本地修订版提供角色 Agent 元数据和额外调用选项，SPEX 当前正式引擎未暴露这些扩展。
原工作流将这些扩展当作必需条件，导致角色已绑定时仍在执行前失败。
用户要求工作流适配现有宿主，不将验收领域约束写进 SPEX。

## 决策

- 角色始终通过官方 Player 端口执行，子流程始终通过官方嵌套 Playbook 端口执行。
- 标准宿主模式不要求 `binding.agent`、额外执行选项、SDK 解析或原生事件回调；Agent、模型、服务与会话由宿主实际绑定管理，未暴露的信息记录为未知。
- 工作流在每次完整 Prompt 中交接目录、权限、图片路径和输出合同；只读角色执行前后核对项目文件，发现越界保留原始结果与变更而不撤销或重放。
- 标准模式保存真实端口调用和返回的原文及身份，将适配层 text/done 明确标为官方返回的投影，不伪造 native init、tool 或 provider done 事件；宿主不暴露的工具次数记为未知。
- 标准模式沿用官方会话续接；角色分配不同 Player，任务通过完整当前上下文隔离，不宣称每次调用都创建新的提供商会话。
- 现有 CLI 本地修订版的详细原生事件能力保持兼容；两种模式共用业务入口、门禁、证据文件和停止边界，未知失败不自动重放。
- SPEX 发布构建生成 format-2 原生入口及子入口依赖闭包，分发所需非引擎资源；安装者不运行 npm 或手工 overlay，UI 负责安装、启用和 Agent 绑定。

## 影响

Prompt 限制与文件检查不等于操作系统沙箱；SPEX 的现有宿主保护仍然适用。
标准模式的完成采纳依据官方角色结果，不假装具备未暴露的原生事件证据或失败会话恢复能力。
本决策不要求修改 SPEX、Playbook 或 Cligent 产品实现。

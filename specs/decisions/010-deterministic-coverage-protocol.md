# DR-010：确定性的覆盖率协议与项目工具后端

## 状态

已接受，细化 [DR-009](009-skill-playbook-responsibility-boundary.md) 的工作流内部职责。
项目后端的报告核验职责由 [DR-011](011-coverage-readiness-and-recount.md) 部分修订：项目工具重算，固定协议作一致性判断并强制完整准备验证。

## 背景

独立对照中，覆盖率准备角色分别生成适配器常量和交接工具描述，名称及版本相同但描述语言不同，整对象比较导致准备失败。
仅修复某次生成文件不能保证新项目或新会话重复成功。

## 决策

- 通用协议入口、工具身份比较、交接元数据和诊断属于 Playbook 包确定性代码。
- 项目后端保留工具选择、实际采集、原生重算、路径转换和统计适配，不自行实现通用准备核验。
- 工具身份是实际名称与版本，用途描述保留作阅读信息，不参与身份比较。
- 每次准备复制完整协议代码与唯一后端绑定到声明测试树，冻结全部字节，使实际执行与归档不依赖原 Skill 路径。
- 完整探针之前实测工具身份；业务执行仍保留真实 stdout、stderr、退出码和成熟工具的原生数据。
- 项目后端失败保留操作、命令、退出状态和原始诊断，不能只记录空断言文字。

## 影响

- 模型不再重复编写通用工具身份校验，项目差异仍通过语言无关的后端 argv 适配。
- 新准备使用固定入口和后端合同，已有历史记录不改写；本次失败与重验分别保存。
- 单次通过不声明稳定性，集成检查后还须在独立干净环境经官方 CLI 完成完整业务链路。

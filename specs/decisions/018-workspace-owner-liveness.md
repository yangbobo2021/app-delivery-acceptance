# DR-018: 受限子进程的工作区拥有者存活证明

## 状态

已接受，依据用户要求修复 SPEX 用例准备的实际阻塞，并保留目录隔离、权限及执行证据。

## 背景

SPEX 当前角色的受限环境拒绝跨进程 signal 0 和进程列表查询，原工作流因此无法核验仍在运行的 Node 工作区拥有者。
将 EPERM 当成存活或删除检查均会丢失租约守卫的依据。

## 决策

- 工作区仍由工作流持有排他租约，SPEX 产品与 Agent 沙箱权限不变。
- 新租约在工作流进程内保留临时签名私钥，以受限进程可访问的本 AT 工作流目录响应一次性随机挑战。
- 签名绑定完整租约、AT、拥有者、输出目录和本次随机挑战；工具权限交接固定公钥，私钥不进入文件、环境、Prompt 或报告。
- 子进程仅在跨进程探测被 EPERM 拒绝时使用新鲜签名证明；无法取得证明、绑定改变、拥有者退出、签名无效或旧响应重放均停止。
- 场景归属记录的 schema、AT 和目录同时核对，证明绑定完整归属记录，工具实际输出限定在该租约尝试及其子目录。
- 原生探测仍可用于可访问的旧租约，缺少新协议的受限旧租约不被推断为存活。
- 证明请求与响应保留为本次证据；释放、异常与中断仍保留原有归属和未知效果恢复边界。

## 影响

文件挑战只证明回答时绑定的拥有者仍在响应，不提供未来存活保证，也不等同操作系统沙箱。
修复属于测试工作流的租约协议，不在 SPEX 内增加验收领域实现。

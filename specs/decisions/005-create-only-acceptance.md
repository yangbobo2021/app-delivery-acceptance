# DR-005: 仅创建交付测试的独立入口

## 状态

已接受，依据用户本轮要求先完成“新建交付测试目录”。

## 背景

用户可以只要求新建交付测试，尚未提供业务需求。
原初始化同时要求非空范围，不能以虚构范围或空需求冻结替代创建容器。
用户已选择宿主理解对话、通过官方 Playbook CLI 分别调用子工作流的方向。

## 决策

- 提供独立的仅创建入口，由宿主显式交接项目根、请求身份及用户原话，通过官方 Playbook CLI 调用。
- 创建是确定性文件操作，使用 Node 工具，不增加负责创建的模型角色；官方 CLI 的 Captain 仍可能调用模型生成面向用户的回复。
- 保存身份、创建依据、本机回执与当前指针；没有范围时不生成范围快照、冻结定义、场景或用例。
- 同一创建请求可核验重入；另一活动验收、身份冲突及不完整产物均明确阻塞，不静默覆盖。
- 保持既有存储格式；后续在同一 AT 中建立首个真实范围，再进入原有冻结及执行流程。
- 本步不迁移其他 Python 工具、不改模型流程和独立复审职责。

## 影响

“已创建”和“已有可执行范围”成为可区分状态。
仅创建不再依赖 Python；原有阶段仍使用原依赖和门禁。
原带范围初始化入口保持兼容，创建入口与原生命周期操作共同保护唯一当前指针。
创建后的文件回执及工作流终态是事实依据，不能仅以 Captain 回复文字或 CLI 退出码证明创建成功。

# DR-003: 按需求优先级逐项开展 P0 场景验收

## 状态

已接受：用户在 2026-10-24 授权建立交付测试目录，对全部需求排序后逐个验证，且每个需求只执行 P0 场景。
本决策将 [DR-001](001-acceptance-requirement-baseline.md) 和 [DR-002](002-requirement-quality-and-identity.md) 中的需求工作阶段推进到限定范围的交付验收，保留原文档阶段的历史。

## 背景

用户指令为：“现在创建交付测试目录，这些需求需要进行优先级排序。然后按优先级，逐个需求进行交付测试验证，每个需求的测试场景只执行P0级别的场景。”
需求基线为审查后的 152 条产品需求，被测代码为主干提交 `fa4a3739336019f17afc9bd6f699361c40efa7ff`。
需求文档尚未提交，验收保存其实际完整文本、源文件快照与内容哈希，不冒称需求已包含在被测代码提交中。

## 决策

- 验收身份为 `AT-20261024-skill-self-p0`，资料根为用户明确选定的测试 SKILL 项目目录。
- 共享范围、定义和结果保存于 `.acceptance/AT-20261024-skill-self-p0`，本机运行资料位于忽略提交的 `.acceptance-local/AT-20261024-skill-self-p0`。
- 需求按具体失败影响排序，核心闭环、授权、数据和证据完整性风险优先，同级按风险及依赖顺序逐项处理。
- 全部 152 条需求纳入，需求优先级与场景等级分别判断，不能因为需求等级高就将全部场景标成 P0。
- 每个目标设计完整场景及义务自检，只选择实际 P0 场景执行，其他等级仍保留在完整清单和分母中。
- 没有 P0 场景的需求记录无本次选中执行项，不自动提高场景等级或宣称该需求通过。
- 场景设计使用现有内部自检流程，用例继续采用查找优先、独立设计评估、真实执行和独立复审。
- 被测产品固定版本，新增或修改测试留在隔离候选工作区；本次授权不包括产品源码修复、提交或 PUSH。
- 本机及可用隔离容器是本轮可执行环境，未进行的原生平台测试明确列为未实测。

## 影响

- 本轮只能给出所选 P0 场景的验收结果及对应限制，不能用它们宣称全部需求或整个项目完整通过。
- 需求排序及逐项执行记录属于本次验收资料，不修改其他项目或将排序写成通用 SKILL 的固定策略。
- 重要阻塞保留具体证据及影响；配置问题通过新尝试修正，产品缺陷如实报告，不修改预期来制造通过。

# DR-021: 原生 Windows 工作流适配

## 状态

已接受（2026-10-30），依据用户授权及安装版 Windows SPEX APP 的真实模块导入失败。
补充 [DR-017](017-standard-host-player-port.md) 和 [DR-020](020-electron-node-subprocesses.md) 的跨宿主执行边界。

## 背景

原生 Windows 的绝对路径含盘符，不能作为 ESM URL 直接动态导入。
本轮要求同一联合包在 Windows APP、Mac APP 与 Codex Skill 中完成需求到单场景执行，覆盖率关闭。

## 决策

- 原生工作流和配置生成均以标准文件 URL 导入实际文件；不修改 SPEX 的业务编排机制。
- 路径归属检查逐段使用当前平台支持的目录分隔符；Windows 的反斜杠不能跳过中间 junction/symlink 检查，POSIX 的合法反斜杠文件名不重新解释为目录。
- 共享产物、场景和测试身份的路径检查同样覆盖 Windows 分隔符；测试目录拒绝 Windows 大小写与尾部点空格造成的受保护元数据目录别名。执行器按当前 PATH/Path 和 PATHEXT 解析实际文件并冻结其真实路径。
- 只读角色的完整文件快照在 Node 自带 Worker 线程中执行同一投影，等待完整结果和线程退出；取消时终止本次拥有的 Worker 并拒绝部分投影，避免 Windows 大目录同步校验冻结 APP 主线程。
- 项目指南 source_basis、白盒来源及复用覆盖率计划使用现有 inside 逐段路径校验，不以 POSIX 字符串前缀检查 Windows 目录归属；仍拒绝绝对路径、上溢及链接逃逸。
- 继续保留独立角色、Prompt 中的目录与能力限制、隔离工作树、排他归属、不可覆盖输入及真实执行和复审证据。
- 遇到 Windows 启动、路径、执行器及结束行为差异，在工作流拥有的接口内修正；不得用跳过校验或扩大产品写入范围换取通过。
- Windows 与 Mac 的实际运行分别保留安装、模型、父子回执和场景结果；声明的支持范围仅覆盖已取得证据的路径。

## 影响

原失败回执保留，以同任务的新请求接续已确认没有未决子效果的执行。
未验证的运行时、覆盖率和平台组合仍须明确标出，单个场景通过不构成全产品通过。

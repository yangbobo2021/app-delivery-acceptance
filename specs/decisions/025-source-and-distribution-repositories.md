# DR-025: 完整源码主干与可追溯安装仓库

## 状态

已接受，依据用户要求：源码仓库保持完整开发结构，SPEX 不兼容时另建安装仓库，从明确源码提交构建对应内容。
补充 [DR-019](019-unified-spex-installation.md) 的分发来源约定；联合安装、角色与业务证据要求保持不变。

## 背景

曾将生成的安装目录直接提交至源码主干，使开发提交、规格与测试分散在开发分支及工作区。
SPEX 当前安装目录使用严格发布格式，不能因此将源码主干替换为发布快照。

## 决策

- 源码主干保留业务源码、规格、测试、构建脚本及其正常合并历史。
- 分发构建读取一个完整、已提交且未修改的源码版本，生成新的独立目录并记录仓库、提交及源码文件摘要。
- 安装仓库保存该构建的联合 Skill/Playbook 内容与来源记录，采用普通提交更新，不反向覆盖源码主干。
- 构建不隐含推送、发布或业务执行，未提交输入、已存在输出及来源校验失败时拒绝。
- Mac SPEX、原生 Windows SPEX、Mac Codex 和原生 Windows Codex 的实际验收分别保存原始调用与业务结果，不用文件导出或历史成功替代本次执行。

## 影响

无需为本轮分发修改 SPEX 的包格式。
旧发布提交及本机历史证据保留；新的源提交与安装提交通过明确来源关联。

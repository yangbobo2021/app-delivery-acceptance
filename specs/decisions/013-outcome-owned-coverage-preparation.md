# DR-013: 以结果定义覆盖率准备与宿主意图边界

## 状态

已接受，依据用户明确要求：覆盖率准备自主构建可采集测试用例覆盖率的执行环境，或说明无法支持的原因，内部排查和修复由工作流承担。
对 [DR-009](009-skill-playbook-responsibility-boundary.md) 的前序资料边界及 [DR-012](012-project-command-generality.md) 的“不自动修复”解释作局部修订。

## 背景

宿主将“执行完整流程、选择一个场景、发现工作流问题后先不修改实现”混入准备 Agent 输入，并在内部自检错误后提前停止准备。
原入口要求宿主拼装运行清单和源码哈希，准备后的程序核验失败也需宿主另发修复请求，不能完整承担准备目标。

## 决策

- Skill 由宿主解释用户意图、授权和跨工作流调度，只向各工作流提供其任务所需的领域事实及目标，不将整段对话或外层调度安排作为全局业务约束下传。
- 覆盖率准备以项目为基本输入，当前目录明确时可省略项目路径；身份、版本、项目检查、源码清单、必要运行准备和就绪核验由该工作流内部完成。
- 原有显式绑定仍可用于已有验收的精确交接，不要求普通调用者生成这些内部文件。
- 准备 Agent 自主选择工具、生成或复用采集代码、诊断和修复环境；程序核验发现问题后将实际诊断及原生资料交回内部继续准备，不把中间一次命令失败直接当作整个任务不能完成。
- 不以修复次数或命令表面形式决定能否修复；受实际调用的有限时间、取消及可用资源约束，停止时说明具体未解决问题，不伪造就绪或将外部服务失败说成项目不支持。
- 项目输入包含发现及运行准备，默认总资源预算为 1800 秒；已有完整绑定的采集准备保持 900 秒默认预算，均可显式调整到实际需要的有限预算。
- 再次为同一项目请求准备时可重新核验当前验收中的可用配置，避免重复生成；不同版本、入口事实或已失效配置不能直接当作当前就绪。
- 准备结论依据实际执行入口的采集、原生数据读取及后续收尾能力；内部失败和修复资料保留，成功前的错误不改写成最终失败，也不丢弃为无错误历史。
- 独立准备不生成业务需求、场景、业务用例或产品通过结论；缺少前序运行资料时可在同一准备目标内复用运行准备能力。

## 影响

简化普通调用输入，使准备和修复在同一公开工作流内闭环。
以真实项目和真实工具验证从项目输入到就绪交接，并用程序核验失败的受控实验验证内部修复和历史保留。

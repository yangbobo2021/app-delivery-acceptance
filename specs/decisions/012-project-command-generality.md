# DR-012: 项目命令透明传递与通用性优先

## 状态

“不自动修复”属于宿主本轮修改实现的安排，不限制覆盖率工作流内部修复；职责澄清见 [DR-013](013-outcome-owned-coverage-preparation.md)。

已接受，依据用户本轮明确要求：先落实放宽检查的版本，再执行一个需求、一个场景的完整流程，遇到问题先记录而不自动修复。
本次实现覆盖命令参数、启动形式、探针事实比较及评估表达限制；故障注入跨阶段变体、存储 worktree 边界与全部阶段恢复不因本次提交被声明完成。

## 背景

通用交付测试会使用空参数、内联脚本、模块、包装器及项目自己的文件名。
此前把命令表面形式和展示预算当作有效性门槛，产生可复现误拒绝。
用户明确要求泛化鲁棒性优先，检查须与实际验收执行及结论适用性有关。

## 决策

- 项目命令按 argv 原样记录及执行，允许后续参数为空字符串，只拒绝缺失执行器、非字符串及进程接口不能接受的 NUL。
- 仅展开框架明确提供的占位标记，其余花括号及参数内容保留。
- 从实际项目 cwd/PATH 解析程序并记录，不用解释器选项白名单、文件名或 argv 中是否直接出现脚本路径推断执行能力或调用图。
- 项目后端及读取器来源、工具使用和实际输出仍保留；独立性判断不能声称仅凭 argv 检查已经证明。
- 探针比较源码范围、组件身份、指标状态与数值，展示描述及顺序不改变这些事实。
- 评估的摘要长度、义务和意见数量是表达与资源安排问题，不作为丢弃实际内容的有效性门槛。
- 临时产品变更可以是测试手段，不能普遍等同于产品修复；尚未实现的变体支持按真实边界报告，不以本次放宽宣布全部支持。

## 影响

保留真实执行、版本及证据关联，删除无关命令形式的误拒绝。
局部集成验证先核对合法反例能执行及实际错误仍可诊断；完整流程使用提交后的固定版本并禁用自动修复，分别记录准备与业务各阶段耗时。

# DR-029: 统一宿主输入与业务源码

## 状态

已接受，依据用户同意将两轮修复统一回源仓库，从同一候选生成 SPEX 和 Codex 两种测试产物；推送等待用户确认。
补充 [DR-015](015-playbook-owned-task-orchestration.md)、[DR-019](019-unified-spex-installation.md) 和 [DR-025](025-source-and-distribution-repositories.md)。

## 背景

Mac 的两轮独立验收分别在源码候选和已安装的原生产物修复了输入、准备、取消及查看问题。
直接合并分发补丁会使原生 Playbook 与导出的 Skill 分叉，且把开发测试放入不接受这些根目录的安装格式。

## 决策

- SPEX 自然语言入口从公开宿主上下文获取项目和会话身份，完整原话转为内部委托；显式 JSON 和 Codex Skill 的原 CLI 委托合同保持兼容。
- 入口归一化不组织子工作流，不补造需求、来源或业务结果；调度仍由总工作流角色持有。
- 两种产物来自同一份工作流源码，宿主适配仅处理实际可用的上下文、取消和 Node/Electron 入口差异。
- 已释放失败、当前活动阶段与已关闭验收分别投影，历史证据不改写；覆盖率采集时间来自经摘要绑定的真实执行回执。
- 本地合并后分别保存两种真实宿主的单场景执行及独立复审证据，定向集成测试和历史成功不替代候选验收。

## 影响

不修改 SPEX、Cligent 或 Playbook 引擎，不放宽目录、权限、归属或执行证据要求。
开发测试与修复记录保留于源仓库；安装仓库由干净、已提交候选重新生成，不直接合并历史分发修补。

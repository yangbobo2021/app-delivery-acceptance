# DR-008: 按工作流职责组织当前实现

## 状态

已接受，依据用户要求“不保留历史包袱、组织结构最清晰，并能通过 Playbook CLI 正确执行对应工作流”。
补充 [DR-007](007-complete-native-workflow-migration.md) 的源码归属及历史执行器退出要求。

## 背景

当前入口已切换至独立工作流，但仍从按演进版本命名的目录加载部分 Node 执行器、提示词及门禁。
旧 Python 调度器和对照测试混入当前 Skill，使目录名称无法准确表达职责。

## 决策

- 工作流专用编排、角色执行器、提示词与校验工具归入对应 `playbook/workflows/<职责>/`。
- 跨工作流的运行时初始化归入 `playbook/runtime/`，公共存储、证据、身份和进程机制继续由明确命名的共享模块承接。
- 当前实现不保留 `v3/`、`v4/` 源码目录、旧编译工作流或旧 Python 调度入口，也不保留转发至新实现的旧路径包装器。
- 当前测试验证当前公开入口和协议，不再依赖旧执行器作为比较基准。
- 已有验收数据仍由当前视图模块只读解析，原证据和结果不因源码整理而改写。
- 保持当前公开工作流命令及输入、停止、身份、证据和权限约定；同步修正静态导入、动态脚本路径、提示词资源及分发引用。

## 影响

维护者可按业务职责定位实现，不需要推断历史版本目录的用途。
依赖检查应覆盖动态调度的执行器和资源；通过官方 CLI 验证全部公开注册入口，并以真实角色调用检查受移动影响的业务链路。
之前已停止的六项目验收不因此自动恢复。

# DR-007: 完整迁移到官方工作流与 Node 工具

## 状态

已接受，依据用户要求完成所有业务迁移并以完全迁移为目标。
源码归属和旧执行器退出由 [DR-008](008-workflow-owned-source-layout.md) 补充。
部分修订 [DR-006](006-independent-workflow-migration.md) 的兼容路径终点；已验证行为与历史资料继续保留。

## 背景

八个独立入口已经验证，其余执行、恢复和生命周期过程仍依赖旧调度器。
仅登记入口或保留旧路由不能证明完整迁移。

## 决策

- 以需求基线的 44 项能力和 22 条用户路径建立完整迁移追踪，未验证项保持未完成。
- 宿主负责理解对话、选择入口和显式交接；工作流负责入口内业务次序、角色绑定、停止与恢复。
- 所有模型调用由官方 Playbook 的 CLI 命令处理器及原生角色端口调度，Skill 不保留独立 SDK 会话循环。
- 锁定官方发布版本；必要的服务配置和冻结图片交接使用显式启动适配，记录实际命令处理器、版本与来源，不修改安装包或伪装为原生 CLI 已具备的参数。
- 未提交测试修改由验收工作流按授权目录、内容基线和独立收据管理，不为满足通用开发工作流提交约定而自动提交测试代码。
- Node 工具承接确定性执行、证据、归档和报告；迁移期间 Python 依赖逐项登记，全部移除并验证前不得宣称目标完成。
- 历史协议可只读保留；完整迁移后新业务请求不得回退旧模型执行器。

## 影响

指定用例重跑、覆盖率修复后重跑、独立关联或评估以及只读历史查看继续是独立用户能力。
运行时升级、写入、模型服务及图像复审分别需要真实前向测试。
不以测试命令退出成功或模型自报完成替代完整业务验收。

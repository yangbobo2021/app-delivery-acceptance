# DR-026: 跨平台 Skill 运行环境的首次准备与复用

## 状态

已接受，依据用户明确授权首次自动下载运行时和依赖到独立缓存，之后复用；Mac、Windows Codex 均须实际验证。
扩展 [DR-019](019-unified-spex-installation.md) 的独立缓存准备边界及 [DR-021](021-native-windows-workflow-portability.md) 的原生 Windows 适配范围。

## 背景

SPEX 导出真实 Skill 不代表外部 Codex 已具备 Node、npm、Git 或可用的原生 CLI 私有存储。
旧准备入口明确拒绝原生 Windows，且锁定 CLI 依赖未包含已实现的 Windows 存储及 Codex PowerShell 修复。

## 决策

- Skill 提供宿主平台可直接调用的准备入口，优先复用兼容的运行时，缺少时下载固定版本并校验摘要后在独立缓存使用，不修改系统 PATH 或全局依赖。
- 源码与运行时缓存保持分离，托管 Skill 目录不写入 node_modules、依赖锁或本机凭据；缓存篡改、下载失败及未知准备归属拒绝而保留证据。
- 原生 Windows 使用真实 Node/npm/Git 和声明了本机权限支持的锁定 CLI；已有目录隔离、租约、角色权限和证据协议不因平台而放宽。
- Agent 登录沿用实际宿主已有配置，构建或分发不携带登录信息；准备结果返回实际可执行文件和包路径供正式配置与官方 CLI 使用。

## 影响

首次使用需要可用网络并发生有记录的下载；后续核验并复用缓存。
Windows 的独立 Node 进程在需要时复用已安装 SPEX 随附的原生运行库搜索路径，不要求用户手工复制 DLL 或修改系统环境；原生模块不可用时仍保留成熟依赖提供的安全后备检查。
Windows 代码缓存采用 LOCALAPPDATA 下的短固定前缀及完整摘要，不沿用可能很深的临时宿主档案目录，以满足原生 Agent 子程序路径限制；身份、来源核验和登录目录保持独立。
四种运行形态的业务成功仍分别由正式执行与独立复审证明。

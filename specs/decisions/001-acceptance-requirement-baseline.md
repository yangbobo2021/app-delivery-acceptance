# DR-001: 为测试 SKILL 建立项目级需求基线

## 状态

已接受：采用用户在 2026-10-24 授权的 SPEX 初始化与需求整理范围。
本决策不认证任何功能已实现或验收通过。
2026-10-24 的质量与唯一身份细化由 [DR-002](002-requirement-quality-and-identity.md) 补充，本决策保留初始整理的历史与来源。
用户后续授权的 P0 场景验收范围由 [DR-003](003-self-acceptance-p0-scope.md) 规定，本决策的仅需求限制描述原文档整理阶段。

## 背景

- 用户要求：“将测试SKILL项目自身也作为测试项目进行验收。”
- 用户限定本轮：“先仅仅只完成补充需求，先不要直接开始交付验收。”
- 项目在初始化前只有 README、SKILL、操作合同和测试资产，没有项目级 SPEC 树及适用的其他需求组织规范。
- 历史知识查询服务当前不可连接；本次以本对话可见的用户要求和仓库现行合同为依据，不推断未能读取的历史决定。
- 现有测试报告是历史实现证据，不作为本次新需求已经符合或通过的证明。

明确的用户目标包括：

> 用例评估AGENT的核心价值：评估测试场景现在关联的用例是否设计合理，是否充分可以验证测试场景，又避免了冗余用例。

> 展示什么信息，不是取决于有什么信息，而是取决于用户希望看到什么。

> 核心的目标就是：确保测试SKILL可以在其他人电脑上高质量的执行任务。

> 我们先一步步开始吧。先不要一个太远的修改，先让测试SKILL可以在关联用例上（已有用例、新建用例）都添加正确的用例ID，先确保测试SKILL自身可以追踪到这些测试用例与测试场景的关系。

## 决策

### 组织及范围

- 在仓库根目录使用 `specs/` 作为本项目的长期需求入口，继续采用 SPEX 原生决策、意图、规约包及条目 ID。
- 需求围绕用户目标和可观察结果组织，不按内部脚本或 AGENT 输出文件逐项反向生成需求。
- 将当前 SKILL 与现行 v4、完整冻结定义 v2 的操作合同作为现有产品约定的整理来源；较早的 acceptance-unit 组织流程和实现示例不自动成为本轮要求。
- 跨包依赖若有实际必要，以条目行内引用表达；本次各包先按封闭职责拆分，避免重复规定同一行为。
- 各包 `验证` 章节只记录尚未开展的状态；按本轮用户限制延后测试条目、场景生成、验收初始化、业务执行和独立验收判定。
- `specs/meta.md` 与 [DR-000](000-spec-structure-format.md) 保留工具原始字节，不改写框架规则来伪装需求已经验证完整。
- 原始产品需求保留在相关外部来源和对话中；本次新条目是其项目级可维护表达，不冒称逐字复制了所有历史对话。

### 来源与职责对应

| 需求包 | 主要约定来源 | 用户价值 |
| --- | --- | --- |
| delivery-acceptance | 当前用户授权、仓库根 README、SKILL 的范围与验收声明 | 知道验收了什么、缺少什么、能否交付 |
| definition-lifecycle | SKILL、`references/frozen-definitions.md` | 固定实际约定、保留出处、正确处理变化 |
| scenario-design | SKILL、`references/portable-workflow-v4.md`、重要程度规约 | 充分而简洁的场景及明确设计缺口 |
| project-preparation | 用户的跨项目/电脑目标、运行环境与 AGENT 运行合同 | 使用项目真实环境，披露未验证能力 |
| case-design | 用户避免漏关联和冗余的要求、查找及复用合同 | 采用当前场景真正需要的用例 |
| case-identity | 用户的源码注释与关联追踪决定、当前用例 ID 合同 | 维护稳定身份并正确追溯源码 |
| case-assessment | 用户关于场景中心、充分性、合理性、冗余和可读输出的要求 | 得到可理解、可核对的设计评估 |
| execution-evidence | SKILL 的真实执行与独立复审约定 | 结论对应真实版本和可信证据 |
| coverage-reporting | 覆盖率工具合同及项目覆盖率协议 | 获得可信工具统计及能力边界 |
| acceptance-storage | 当前验收、知识索引、归档和清理合同 | 可恢复、可共享且不混用证据 |
| traceability-view | 用户的统一追踪价值边界、追踪与统计合同 | 从需求直观看关系和完整状态 |

操作资料实际位于 `skills/en/app-delivery-acceptance/` 的 `SKILL.md` 与 `references/`。
这些来源只说明本次如何整理需求，不证明实现符合性。

- 初始化提示项目未配置 `git user.name`；本轮不配置 Git 身份、不提交或 PUSH。

## 影响

- 后续维护先从 `specs/map.md` 定位需求，再核对相关实现与操作规约。
- 需求条目获得稳定 ID，未来可以作为场景的独立输入；当前没有生成这些场景或任何验收通过记录。
- 所有既有未提交代码、测试及历史报告继续保留，本轮只新增规格资料和 SPEX 初始化所需的 AGENT 入口。
- macOS/Linux 是当前文档声明的运行前提范围；原生 Windows 未列为现有运行支持，本次未新增跨平台实测声明。
- TDD 模式、全项目用例普查及外部测试管理平台不在本轮需求扩展范围。

# DR-014: 宿主推动跨工作流任务接续

## 状态

已接受，依据用户明确要求：主 Agent 应推动 Playbook 工作流调用完成最终任务，准备遗漏可修复并继续。
补充 [DR-009](009-skill-playbook-responsibility-boundary.md) 的跨工作流调度与 [DR-013](013-outcome-owned-coverage-preparation.md) 的内部准备修复，不改变独立工作流的停止边界。

## 背景

真实场景用例已完成业务调试，但现有覆盖率准备没有采集产品子进程。
用例工作流如实返回 blocked，宿主将其作为整个任务终点，没有将实际进程事实交回准备后继续。

## 决策

- 主 Agent 保持用户授权的最终目标与停止点，依据实际回执和证据选择后续公开工作流。
- 可修复的跨阶段前提缺口交回其所属工作流，内部修复和核验仍由该工作流承担，不在 Skill 增加业务调度脚本或强制主路由。
- 准备完成以实际验证路径为适用范围，新路径遗漏触发有诊断的新准备和重新绑定，不改写历史 ready、失败或原始证据。
- 接续保留同一验收、选定场景、已有测试及永久身份，避免重新设计和无关重跑。
- 活跃归属与未知效果先通过恢复入口核查，不删除声明或盲目重演；实际授权、输入、取消和资源限制仍是停止依据。
- 不引入通用修复次数、命令形状或语言白名单；无实际进展的相同失败不反复重发。

## 影响

独立工作流仍可由人或 CI 单独调用并停止，Skill 接入则指导宿主组合调用直至所请求结果完成或出现真实阻塞。
验收以保留的真实失败为起点，核对准备修复、重新绑定、同场景与用例接续及独立证据，不以指令文本匹配代替执行。

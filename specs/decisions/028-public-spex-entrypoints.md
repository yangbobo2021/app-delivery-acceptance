# DR-028: 联合包的主工作流与 Skill 独立公开

## 状态

已接受，依据用户要求修复两个仓库及本机安装中主工作流不可见的问题。
补充 [DR-019](019-unified-spex-installation.md) 的联合安装选择约定，不改变业务调度、权限、隔离或执行证据规则。

## 背景

当前 SPEX 将另一类型工件通过 `requires` 引用的目标视为内部支撑。
旧产物让主 Playbook 依赖真实 Skill，Skill 又依赖主 Playbook，导致文件均安装而两个入口均未公开。
只统计声明数量或加载注册模块不能发现这个问题。

## 决策

- 真实 Skill 与全部原生 Playbook 均为独立公开工件。
- 主工作流与子工作流保留同类型依赖闭包，不声明用于强制联合选择的跨类型相互依赖。
- 完整包的默认工件选择同时安装两种入口，显式工件选择继续遵循 SPEX 原有规则。
- 使用实际 SPEX 发现实现核对 31 个公开 Playbook 与一个真实 Skill，另行验证本机安装、锁文件及 Agent 导出保持一致。

## 影响

只调整测试包的分发声明及对应验证，不修改 SPEX 或业务工作流实现。
文件发现与导出通过不替代真实模型业务执行验收。

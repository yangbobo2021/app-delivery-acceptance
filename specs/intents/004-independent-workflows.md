# IR-004: 独立交付测试入口逐项实现

## 状态

已完成本轮业务迁移与所列验收，形成 30 个正常独立入口及 44 项能力、22 条用户路径追踪。
实测平台、模型组合及恢复边界保留在验证记录，不据此声明全部项目或平台组合已通过。

## 意图

在保留现有用户能力和历史协议的前提下，将可独立请求的过程接入官方 Playbook CLI。
具体职责与最终兼容约束见 [DR-007](../decisions/007-complete-native-workflow-migration.md)。

## 任务

1. 接入确定性创建与冻结，分别验证停止边界及存储兼容。
2. 接入场景设计角色并验证 create/edit，保留人工改动及无关目标。
3. 对其余能力按依赖及用户价值逐项接入，不把旧入口存在当作已迁移完成。
4. 汇总每项输入、命令、实际模型调用、产物、失败与重验记录。

## 验证

- 每个入口分别保存确定性协议检查和真实 CLI 回执；协议夹具不冒充真实模型产物。
- 变更触及共享协议时运行存储、冻结定义、场景修订等相关回归。
- 选定 46 个通过批次共 328 项检查；详细范围、真实 CLI、协议夹具、失败与重验分开保存。
- 30 个入口都有真实官方 CLI 调用；不同的原始失败尝试保留，未改写为成功。
- 当前状态及证据索引见[迁移追踪](../../reviews/full-workflow-migration-trace.json)。

## 已验证范围与保留边界

已升级官方运行时并加入显式命令启动适配，Codex 服务路由、冻结像素交接、未提交测试写入及同会话继续已有真实证据。
Claude Code 与 OpenCode／GLM 同服务的实际写入、JSON 回执和会话继续已验证。
正常业务使用 Node；项目自己的解释器或成熟覆盖率工具仍按实际项目准备，历史 Python 文件仅作历史/开发对照。
失败调用的官方根会话 ID 不证明后端可连续恢复；已完成工作可采用，未知副作用必须先核对并显式处理，禁止自动重放。
macOS arm64 已前向实测，Linux 不冒充已实测，原生 Windows 尚不支持。
本轮没有提交、PUSH 或发布新包，也没有重新宣称 SPEX 产品及旧 AT 已交付通过。

## 已实现

- 查找、生成和差量修复统一使用普通源码注释：`@case-id: TC-<UUIDv4>`，按源码语法使用 `#`、`//` 等注释。ID 由宿主工具分配，已有标记原样复用。
- 只处理本次实际关联的测试声明。查找 Agent 仍只读，宿主在核对原始结果后只添加可验证的 ID 注释。`existing_only` 的源码正文、断言、文件集合及权限仍受保护。
- 更新最终结果中的用例 ID、场景引用、行号和源码哈希；保留原始 Agent 字节和旧调试凭证。评估的 C1 等短引用通过 original_id 对应永久 ID，正式执行与复审核对添加注释后的文件。
- 项目共享 `.acceptance/case-identities.json` 保存已关联身份和场景关系。同一用例跨场景复用；跨验收且源码尚未集成时，仅按完全一致的定位、标题和正文复用。不按相似标题猜测。
- 用例详情显示永久 ID 和源码注释位置；归档保留身份资料。移开本地执行目录后，归档视图仍可显示这些字段。历史记录保持原样。
- 声明的测试范围支持目录和精确文件，根目录测试文件不需要开放整个项目。相邻文件仍被拒绝。文档中的 ID 示例不会被当作测试声明。

源码注释沿用现有的隔离候选工作区流程，原开发目录中的测试代码不被静默改写。集成候选测试时，应同时保留源码注释和项目共享索引。

## 边界

本次原生环境为 macOS，调用者为 Codex / gpt-6.1-sol / high。Linux、Windows 未进行本次原生实测；CRLF 检查不等价于 Windows 实测。

本功能不枚举全项目所有用例。注释语法或声明位置无法可靠确定、动态测试无法独立定位、ID 冲突等情况会明确阻止交接。参数化声明使用一个 ID；已有注释随测试移动或修订保留。丢失标记且源码已经变化时，不保证自动恢复旧身份。命令凭证绑定文件和执行入口，不据此声称每个关联用例单独运行通过。
